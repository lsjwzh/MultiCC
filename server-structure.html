进一步模块化拆分建议

1. Chat Turn 引擎 → src/chat/turn-engine.js HIGH · ~1060 lines
Lines 4701–5760 · runChatTurn + spawnChat + handleLine + forward + runChatTurnStreaming + finalizeStreamingTurn
这是 server.js 中最大的单一功能块。已有 src/chat/ 目录和 host-runtime/turn-lifecycle 等模块， 但核心的「spawn CLI 进程 → 逐行解析 → 事件分发 → 流式转发」主循环仍在 server.js。 可抽为 createTurnEngine(deps) 返回 { admitChatWork, runChatTurn, runChatTurnStreaming, finalizeStreamingTurn }。 依赖注入：provider registry, chatStream, broadcast, classify hooks, orchestration outbox。
2. Session CRUD 路由 → src/routes/session-crud.js HIGH · ~1000 lines
Lines 1961–2870 · PATCH / fork / bundle / import / delete / relocate / restart / notes
session-create 已抽出，但 session 的修改/删除/fork/导出/导入/迁移仍在 server.js。 可合并为 createSessionCrudRoutes(deps) 一次 mount。 注意：bundle encrypt/decrypt 可独立为 src/session-bundle.js 供 import/export 共用。
3. Classify 状态机 → src/classify/state-machine.js MED · ~720 lines
Lines 3551–4270 · recordTaskBoardGoal + dispatchStateAction + scanAndReclassify + runClassifyNow + classifyTurnEnd + ensureCurrentTask
src/classify/ 目前只有 vocab.js 和 user-input-host.js。核心状态机（P/A/E/D 状态转换、 scan pass、reclassify 逻辑）全在 server.js。可抽为 createClassifyEngine(deps)。 注意与 taskBoard routes 的交互——routes 读写状态，engine 驱动转换。
4. 事件适配层 → src/chat/event-adapter.js MED · ~430 lines
Lines 4271–4700 · applyClaudeChatEvent + applyAdapterChatEvent + emitTurnOutcome + emitRunningNotify
这层把 CLI 原始事件翻译成 classify/taskBoard/UI 能理解的结构化事件。 与 turn-engine 紧耦合但职责不同（解析 vs 执行），适合独立为 event-adapter。
5. Dispatch 系统 → src/dispatch/engine.js MED · ~395 lines
Lines 1061–1365 + 2871–2960 · dispatchToSession + finalizeDispatch + maybeDispatchFromChatTurn + contract handler
src/dispatch/ 已有 targeting/markers/terminal-target-policy，但调度主循环仍在 server.js。 可抽为 createDispatchEngine(deps) 返回 { dispatchToSession, finalizeDispatch, maybeDispatchFromChatTurn }。
6. WebSocket 层 → src/ws/ LOW · ~450 lines
Lines 5761–6210 · handleChatWs + wss.on('connection') + upload + broadcast
WS 是胶水层，连接前端和所有后端子系统。抽出收益中等，但能减少 server.js 对 ws 协议的直接管理。 可拆为 src/ws/chat-handler.js + src/ws/connection-manager.js。 风险：WS handler 大量闭包引用 server.js 局部变量，需要仔细梳理依赖注入。
7. Session 生命周期 → src/session/lifecycle.js LOW · ~325 lines
Lines 1366–1690 · allocateSessionId + createSession + onStreamEnd + livenessRolloutPath
createSession 是全局最复杂的工厂函数之一（含 worktree 创建、CLI spawn、stream 监听）。 抽出后可与 session-crud routes 解耦。但依赖极多（~20 个外部引用），优先级放后。
