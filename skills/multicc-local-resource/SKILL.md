# multicc-local-resource

> 本机文件在聊天里能不能看见，取决于路径怎么写。写对了，multicc 自动「本地路径 → 服务路由」。

## 机制（不用你做转换）

聊天前端（Web 与 App 同一套规则）在渲染 Markdown 时，把**绝对路径**的图片/链接改写成
`/api/download?path=<绝对路径>&inline=1`，由 multicc 服务从本机磁盘读出来。所以你只需要：

- 图片：`![说明](/绝对/路径/图.png)` —— 行内显示，点击可放大。
- 其他文件：`[文件名](/绝对/路径/报告.pdf)` —— 点击下载/预览。

**不要**自己拼 `http://127.0.0.1:3000/api/download?...`、不要转 base64、不要把图片先上传到外站。

## 路径必须满足

1. **绝对路径**，且以这些根之一开头：`/tmp` `/Users` `/home` `/var` `/private` `/opt` `/Volumes` `/mnt` `/root` `/data`，
   或 Windows 盘符 `C:\` / `C:/`，或 `file:///…`。`~/x.png`、相对路径、其他根（如 `/srv`）**不会被转换**——
   先 `cp` 到 `/tmp` 再引用。
2. **文件真实存在**：贴之前 `ls` 一下；不要凭记忆编路径。
3. **路径里有空格时必须用尖括号包住**：`![图](</Users/me/社媒 照片.png>)`。
   不加 `<>`，Markdown 根本不会把它当成图片，原样显示成文本。
4. **中文/非 ASCII 文件名可以直接写**，不要自己做 `%E7%A4%BE…` 百分号编码。
   （渲染器会编码一次；服务端 `/api/download` 对「字面路径不存在但含 `%XX`」会解码重试，所以即使被多编码一次也能找到。）
5. 文件名里有 `)` 或 `]` 也用 `<>` 包住，或者先改个干净的文件名。
6. 只能是文件，目录不能展示/下载。

## 常用写法

```markdown
![登录页截图](/Users/me/.multicc/assist/task-1/登录页.png)
![带空格](</tmp/shots/step 1.png>)
[完整日志下载](/tmp/build/run.log)
```

## 失败自检

用户看到 `⚠ 无法加载图片: <路径>` 或点链接 404 时，按顺序查：

1. 文件在不在：`ls -l "<路径>"`（注意显示的路径若含 `%E7…`，解码后再查）。
2. 路径是否落在上面的受支持根里；不在就复制到 `/tmp/…` 再引用。
3. 是否带空格/括号却没加 `<>`。
4. 服务是否是旧版本：旧服务不认多编码路径，需要用户**手动**重启 multicc 后再试（你不要自己重启服务）。
5. 排除以上仍失败：用 `curl -s -o /dev/null -w '%{http_code}' --get "$MULTICC_BASE_URL/api/download" --data-urlencode "path=<路径>" --data-urlencode inline=1`
   看服务端返回码（需带登录态，在受限环境可能 401，401 不代表路径错）。

## 什么时候改用别的技能

| 需求 | 用 |
|---|---|
| 要把内容发给聊天**之外**的人 / 手机经隧道免登录打开 / 生成可分享网页 | `multicc-artifact`（临时链接，无需登录） |
| 展示的是**远程屏幕**让用户亲手操作 | `multicc-human-assist` |
| 截图要让用户圈点标注 | `multicc-human-assist` 的截图标注路径（截图放 `~/.multicc/assist/$MULTICC_SESSION_ID/`） |

截图类图片建议存放在 `~/.multicc/assist/$MULTICC_SESSION_ID/`（7 天自动清理）；不要把含敏感信息的截图发布成临时产物。
