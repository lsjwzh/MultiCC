# multicc-human-assist

> AI 解决不了的问题，别硬试——发个链接，让人直接上手。

核心原则：卡住时**主动**求助，而不是换着花样重试。有些场景（滑块验证码）连续失败会进入必拒态，越试越糟；有些环节（2FA、密码、生物确认）本质上只有人能完成。一次到位的人工介入，比十次盲试便宜。

## 何时必须求助（判断标准）

- 同一个物理步骤（点击 / 拖拽 / 输入）已失败 **2 次**：停下求助。
- 环节只能由人完成：2FA 验证码、短信/邮箱确认码、生物识别、密码、真实身份意图判定。
- 屏幕内容 AI 辨认不清、不确定点哪里：与其猜坐标，不如让用户指。
- 用户正在物理使用机器（人在打字 / 握鼠标）：抢输入前先问。

## 能力选择（按任务需求）

| 场景 | 用哪个 |
|---|---|
| 需要人的「手」：拖滑块、点按钮、输密码、扫码 | 远程操作链接 |
| 目标太小 / 太密（小按钮、密集列表、验证码缺口）：直接点不准 | 远程链接 + 提示用户框选/捏合放大后再点 |
| 需要人的「眼 / 判断」：告诉 AI 点哪里、这是什么、结果对不对 | 截图标注 |
| AI 找不到目标位置，但确认后要人上手 | 先截图让用户圈位置，再发远程链接 |
| 只要用户看一眼结果对不对 | 远程链接（只看模式 `#rs=1`） |

求助要说得**具体**：让用户动哪个窗口、哪个控件、期望发生什么。「帮我看下这台机器」不如「打开链接后，把登录窗口里收到的 6 位验证码填进来」。

## 能力一：远程操作直达链接（需要用户动手时首选）

在聊天消息里直接发 Markdown 链接（**发之前先说明要用户做什么**）：

```
这一步需要你亲手操作：[🖥 点这里直接操作屏幕](#rs=control)
打开后请把滑块拖到缺口处。
```

- `#rs=control`：点开自动展开「🖥 屏幕」浮层并进入**可操作**模式。hash 链接不动本页任务参数、无需知道 task id、点开即达。
- `#rs=1`：只要用户看一眼屏幕（只看模式，不发送任何输入）。
- **按端自动路由，发同一条链接即可，不用分端**：
  - web：聊天页原地展开「🖥 屏幕」浮层（`#rs=control` 直接进入可操作模式）。
  - App：点链接直接推入原生「屏幕」页，不走浏览器；`#rs=control` 进页即可操作，`#rs=1` 只看。原生页支持捏合缩放、⛶ 框选、长按 450ms=右键、⬆⬇ 滚动、键盘条；也可从聊天页 ⋯ 菜单手动进入。
  - 跨设备完整链接（下方）在 App 里同样被识别：只要 origin 是当前连接的服务器（或 root-relative `/chat.html?...&rs=`），也走原生页；外站链接里的 `rs` 不拦截。
- 本机按 Esc 随时急停；浮层右上「✕」关闭即释放操作租约。

跨设备发完整链接（复制到微信 / 在别的电脑打开）时用：

```
http://<host>:3000/chat.html?air=1&task=<taskId>&rs=control
```

（task id 从任务卡或 git log 里 `multicc: session task-<id>` 提交查；拿不到就发 `/air` 目录首页让用户点进任务再说。）

### 区域精确控制（小目标 / 密集界面）

屏幕铺满视口后小目标未必点得准，指引用户用局部放大，可以只针对要操作的区域：

- **⛶ 框选清晰化**：点工具栏「⛶」，在画面上拖一个矩形圈住目标，松开后重新截取原始画面，先按原生像素裁剪，再单独压缩选区并铺满视口。细节来自压缩前的源图；选区实时刷新，可继续框选更小区域。web 与 App 原生入口均支持。
- **坐标规则**：选区保留原屏幕逻辑坐标的起点和范围；点按、右键、标注与重新框选都会加回选区偏移。切换画面未完成时不可操作旧图。
- **双指捏合**：随时缩放，web 1–5×、App 1–6×，中点锚定跟随手指。捏合只改变显示大小；需要恢复小字细节时使用框选清晰化。
- 放大后：**单指拖动=平移**、**原地点一下=精确单击**（选区图未额外捏合时，web 仍可拖拽；App 选区的轻点、拖拽和长按右键走同一坐标映射）、**快速点两下=复位**、右上角 **“全屏” / % 徽标点击=复位**。
- **右键**：web 工具栏「右键」按钮点亮后，下一次点击（鼠标 / 触屏一致）按右键发出、按钮自动熄灭；拖动超过轻点阈值视为取消不消耗。App 原生入口直接**长按 450ms=右键**。
- 远程画面上「✎ 标注」可冻结当前帧；用户画的标记（点=单击、框=点中心、箭头=拖拽）开「实时透传」后直接在本机执行。

### 护栏与注意事项

- 用户操作期间 AI **不要同时发输入指令**——操作租约在用户手里，Agent 会拒绝；等用户回复完成。
- 发完链接就结束本轮等用户，不要轮询催促。
- 锁屏状态下远程操作会被拒绝（除非该机已配好自动解锁）：先确认屏幕解锁状态。
- 缺「屏幕录制 / 辅助功能」授权时，浮层会自带引导条（仅本机能点「打开设置」），不用额外解释。

## 能力二：截图标注（用户只需指位置，不用动手）

1. 截图存 `~/.multicc/assist/<sessionId>/`（该目录 7 天自动清理，不要走 artifacts）。
2. 消息里用 `![step N](/absolute/path.png)` 展示，配一句要用户做什么。
3. 调 `wait_for_user_answer` 结束本轮；用户在图上「Annotate」画标记回传。
4. 回答形如 `[annotation] src=<path> size=WxH` … `[/annotation]`：`#n point/box/arrow x,y`（坐标已归一化 0..1，乘截图的坐标基还原；远程选区截图旁的 `<src>.json` 保存 `x/y/width/height`，AI 操作前先读它，并加回偏移），可带 ` — 备注` 与 `note: 总指令`。优先把标记解析成真实元素再操作；执行后回贴结果截图让用户确认。
5. AI 需要看清细节时，用 `../multicc-computer-use/scripts/mcu.sh snap-hires <绝对.png路径> W H X Y`（W/H/X/Y 均是逻辑点）；原生截图像素须按 `X + u×W, Y + v×H` 映射回屏幕。浏览器截图用 CDP `Page.captureScreenshot` 的 `clip`（CSS 像素）从页面源头截取，保存 viewport/clip 坐标基。不要裁剪已经压缩的聊天缩略图。
6. 页面已变化时（截图过期）重新截再问，别拿旧图坐标硬点。

## 边界

- 不得用求助通道绕过用户已拒绝的授权或操作。
- 涉及密码 / 密钥：值只能进 MultiCC 保险箱（secrets vault），绝不让用户粘贴进聊天。
- 求助不是失败：一次到位的人工介入，比十次盲试便宜。
