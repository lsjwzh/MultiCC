MultiCC 异常处理与展示蓝图

把 HTTP、WebSocket、外部 Fleet、Provider/Relay、CLI 与宿主生命周期异常统一成可分类、可追踪、可行动的错误对象，再由同一个展示策略选择状态栏、横幅、表单、事件卡或调试详情。
ERROR UX · TARGET ARCHITECTURE

当前确认的断点

  • • WebSocket 取票失败在 chat.js 被统一写成“授权失败”
  • • auth-client.js 只抛 HTTP 状态，响应 DTO 与追踪号丢失
  • • REST 与 WS 仍大量使用各自的纯字符串错误结构
  • • Toast、系统消息、状态栏、表单红字由页面自行选择

目标行为

  • • 401/403 才显示登录失效或权限不足
  • • 502/503 明确显示本机服务或远端 Fleet 不可达
  • • Provider 409 显示路由 attempt 已过期并建议重试本轮
  • • 上游模型、配额、限流、超时分别展示，不再统称网络错误

落地顺序

  • • P0：统一浏览器 ErrorEnvelope 解析器与 WS 连接分类
  • • P1：统一展示路由器，收敛 Chat 与 Manage 的重复逻辑
  • • P1：补齐 Provider / External Fleet 的结构化错误 DTO
  • • P2：加入可展开诊断详情和 correlationId 跨实例串联
