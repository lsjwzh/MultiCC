# 任务壳分叉实验：发布测试方案

日期：2026-09-06。本文是当前实施与验收契约，替代 `task-session-shell-experiment.md` 中同任务默认排队、分叉汇合的旧设想。

## 行为与范围

普通 Web chat 可主动打开实验任务壳。壳关联独立任务；空闲续作，占用时明确的独立工作从已完成历史快照分叉。分叉不汇合、不自动合并 Git。多个壳可关联同一任务；之后新任务可显式引用多个任务的版本化上下文。任务历史仍由现有隐藏聊天会话保存，SQLite 仅保存壳、绑定、不可变快照和投递凭据。

第一阶段使用明确意图（工作、调整、回答、取消），不让模型猜测决定控制消息去向。壳内默认关注任务，用户可选择已有任务或新建。未完成依赖必须等待用户在结果就绪后重试，不以复制假装依赖完成。公开分享、跨项目、原生 JSONL 改写、自动历史清理和 CLI 内存热复制均不进入本实验。

## 测试先行与发布门槛

先写可执行失败用例并确认失败，再实现；测试全部使用临时目录、隔离数据库和受控执行器。新测试加入 npm 脚本。发布前执行新增单元/HTTP/隔离进程测试、现有受影响回归、npm test 与治理检查。报告区分假 CLI 确定性验证与真实提供商测试，不用前者冒充后者。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| R01 | 空闲任务续作 | taskId / executionSessionId 保持，当前壳历史不成为隐式上下文 |
| R02 | 任务占用，新独立工作 | 新 taskId / sessionId / 工作区；记录 fork 来源；无汇合与自动 Git merge |
| R03 | 两壳同时投递到空闲任务 | 同步持久预留使一个续作、另一个分叉 |
| R04 | 同一消息超时重试、并发重复 | 同一目标、同一投递键、至多一个正在创建的执行器；改内容复用键返回冲突 |
| R05 | 两壳使用相同 clientMsgId | 两条独立消息，不互相去重 |
| C01 | 来源仍在输出 | 快照只含已完成回合；不含 interim、partial、cancelled、error 和当前回合 |
| C02 | 后续修改来源历史 | 已保存快照内容/哈希不变；保留来源消息 ID、工具证据 |
| C03 | 新任务引用两分支 | 仅注入所选有界版本；不合并任务、不递归展开祖先 |
| C04 | 引用未完成结果作为依赖 | 拒绝执行并给出依赖未就绪；无新进程 |
| I01 | 回答 / 调整 / 取消 | 绑定原 task + turn / requestId；不分叉；过期控制返回冲突 |
| I02 | 跨壳同问题不同答案 | 一次结算；后来的不同答案冲突 |
| I03 | 原生入口绕过实验路由 | 普通用户输入被拒；系统续接保持原执行身份；不得改到其他 taskId |
| F01 | 创建工作区失败 | 凭据保留目标与原始脱敏错误；同键恢复继续创建原目标 |
| F02 | 入队已成功但响应/回执保存失败 | 同键交由现有持久队列去重；不改目标，不启动第二执行 |
| F03 | 重启恢复预留 | 保留凭据；重试原请求恢复；不把未知投递状态当空闲 |
| S01 | 跨项目关联/快照/任务引用、畸形输入 | 拒绝且不启动执行；缺必需字段返回明确错误 |
| S02 | 删除壳 | 只删除关联，任务历史和其他壳不受影响 |
| S03 | 关闭实验 | 新入口关闭，已有执行可结束、历史仍可读；不迁移旧历史 |
| U01 | 页面选择、忙时分叉、重试与问题回答 | 目标及分叉来源可见；发送失败保留内容和请求键；取消精确指向当前显示回合 |
| E01 | 隔离宿主 + 假 CLI + Git 仓库 | HTTP → 持久预留 → 独立工作区 → prompt → 正式历史全链路验证 |

## 副作用与应对

- 分叉增加工作区、进程和 token 成本；已有调度限额继续生效，壳不会绕过资源调度。
- 快照可能落后于来源当前工作；页面与 seed 标注只含完成回合，独立工作区从已记录 Git 基线开始，不含未提交文件。
- 历史中的结论可能冲突；注入带来源/哈希的引用资料，不自动覆盖为唯一真相。工具结果作为资料，不重放工具调用。
- SQLite 与现有队列是两个持久边界；采用先保存目标、再用稳定消息键投递的重试协议，不能保证外部工具副作用 exactly-once。
- 未确认投递保留占用，牺牲部分可用性以防重复；页面提供同键重试，保留错误供诊断。
- 首版不做语义自动归集；任务选择是可见确定性规则，可在后续带误判数据的实验中增加模型判定。
