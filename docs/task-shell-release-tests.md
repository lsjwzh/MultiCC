# 任务壳按需上下文：发布测试与对比方案

日期：2026-09-06。本文是“默认续接最后任务、按需回补壳上下文、事后安全归集”的测试与发布契约。功能设计见 [任务会话壳方案](task-session-shell-experiment.md)。

## 行为不变量

- 普通消息只由服务端 `currentTaskId` 路由；URL、浏览器缓存和客户端 taskId 不能改写目标。
- 当前任务占用时进入同一任务队列，不自动创建任务或工作区。
- 只有用户点击「新任务」后发送，才会在执行前创建独立任务、隐藏会话和 Git worktree。
- 每轮默认只使用当前任务原生上下文；其他关联任务的完成历史只可由只读 MCP `get_task_context` 有界回补。
- 回补内容保留 taskId、消息来源和完整回合边界；历史内容只作为资料，不能作为新指令执行。
- 只读回合允许 Aux 事后归到已有或新任务，并原子更新 `currentTaskId`；出现写入、提交、部署或未知工具时不得跨任务迁移。
- token 提示是省略上下文的估算值；一旦本轮调用回补 MCP，显示节省为 0，并保留原估算值供解释和审计。

## 离线 A/B/C 对比

比较单位是“同一个脱敏对话在同一目标轮次的重放”，不能用不同问题直接比较 token 或正确率。

| 组别 | 输入策略 | 用途 |
| --- | --- | --- |
| A：全量基线 | 当前任务上下文 + 壳内其他任务全部可用完成历史，每轮预注入 | 对照旧的高成本做法 |
| B：按需方案 | 仅当前任务上下文；模型判断必要时调用 `get_task_context` | 候选发布方案 |
| C：无回补消融 | 仅当前任务上下文，禁用回补工具 | 衡量 MCP 对质量的净贡献，不进入生产 |

语料至少覆盖：直接续作、代词指代、跨任务约束、相似任务干扰、明确新主题、需要旧结论但不需要旧过程、错误或冲突历史、写代码/提交/部署等副作用任务。优先使用脱敏真实样本，再补合成边界样本；同一 case 在三组使用相同模型、provider、effort、系统提示、工具状态和代码基线，并随机执行顺序。非确定模型每 case 至少重放 3 次。

记录以下原始事实，不只记录总分：provider 实际 input/output/cache tokens、回补调用次数和时点、首 token 与总延迟、最终 taskId、是否新建任务、工具调用与文件差异、答案中的事实断言。UI 估算值单独记录，不能冒充 provider 计费数据。

人工评分应隐藏组别，按预先写好的 case rubric 判断：任务完成、旧约束召回、无关上下文污染、是否应回补、任务归集、工作区一致性。自动判分只用于稳定事实（taskId、工具、文件、token、延迟），开放式答案至少双人或“规则 + 模型裁判 + 抽样复核”。

建议发布门槛：B 相对 A 的任务完成率非劣界不低于 -3 个百分点；需要旧上下文的漏回补率不高于 2%；不需要时的误回补率不高于 10%；任务归集 macro-F1 不低于 0.95；错误工作区写入、重复执行和跨项目泄露必须为 0；实际输入 token 中位数至少下降 20%。这些是上线门槛，不是当前自动化测试已经证明的结论。

## 在线灰度

按稳定的 shellId 哈希分桶，避免同一用户跨组漂移。先内部 dogfood，再按 5% → 25% → 100% 放量；每阶段至少覆盖一个完整工作周期。线上只比较 A 与 B，不启用 C。

立即回滚条件：任何跨项目上下文泄露、错误工作区写入、重复副作用、任务指针不可恢复；或 B 的上下文相关失败率连续两个观察窗高于 A 3 个百分点。性能类回滚条件为 p95 总延迟增加超过 20%，或 token 中位数未下降且误回补率超过 10%。回滚只切换新回合的上下文策略，不迁移或删除已有任务、receipt 和历史。
