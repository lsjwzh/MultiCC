# 额度存储与轮询迁移

额度缓存的 SQLite 打开、旧 JSON 导入、读写、并发合并和清理由 `native/core/src/provider_limit_store.rs` 持有，Node 通过异步原生接口提交操作。服务在缓存完成初始化后才监听请求，关闭时先排空额度操作。旧 JSON 在导入和核对后归档；订阅表先于额度表创建时，额度表与导入数据在同一事务内添加，保留原有订阅数据。旧 JSON 与已有记录发生无法证明安全的冲突时，启动失败并保留原文件。

自动选线按一次已提交快照计算，代理最终拨号前再次异步检查额度和当前轮次。虚拟线路失败的额度更新与读取原有窗口在同一 SQLite 事务中完成。额度查询本身失败时，代理额度保护拒绝该次拨号；其他非关键展示仍按原有策略降级。轮询缓存、有效期、在途去重和结果归一化由 Rust 持有；Node 保留网络适配器、出口检查及等待网络结果的 Promise 桥，待网络与宿主生命周期迁移后删除。同步网络适配错误不再留下永久在途的轮询项。

`tests/helpers/legacy-provider-limit-cache.js` 是仅用于差分验证的冻结 Node 实现，不参与生产装配。订阅展示的既有跨进程最终一致语义不属于此次额度缓存改动。
