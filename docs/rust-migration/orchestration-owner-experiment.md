# 编排 SQLite 独立 Rust 所有者

状态（2026-11-16）：当前工作区的正式存储入口已改用独立 Rust 所有者，
Rust 检查和目标回归已通过，全量 npm 仍有下述 8 处失败。尚未提交、合并或重启服务；
这不表示调度迁移或整个后端迁移完成。

## 当前实现

同一进程内不同 SQLite 实现打开同一文件后，其中一个连接关闭可能破坏另一个实现
对 WAL 锁的认知。`revision` 和 `data_version` 在该场景不构成可靠保护。
`createOrchestrationSqliteStore` 现在只通过 `RustIsolatedOrchestrationStore`
打开独立 Rust 进程，正式入口不再选择同进程 `RustOrchestrationStore`。
底层同进程类仍供原生内核与混合驱动诊断测试使用，不是生产回退路径。

所有者入口是配套 `multicc-gateway orchestration-owner`，只服务私有标准输入/输出
协议，不开启 HTTP 端口，也不启动 Node。二进制从实际加载的 addon 同目录定位，
源码、desktop 和 standalone 继续复用已有配套产物。`ownerBinary` 仅供隔离测试或
显式嵌入入口注入绝对路径，不改变所有权模型；不搜索 PATH。
二进制缺失、不可执行或协议不兼容时打开失败，不静默回退。

原批要求存储 addon 协议 **11**、所有者协议 **5**；后续调度元数据实验已将
所有者协议增至 **6**。必须配套构建、分发和验证；
不要把新宿主与旧 addon/二进制混装。未改动数据库 schema、既有 JSON 格式或客户端 API。
本批不授权直接替换运行中的所有者，也不触碰真实数据库。

宿主通过长度前缀帧发送请求，事务由 Rust 所有者处理。
传输失败时客户端终止所有者，不自动重放可能已经提交的请求；
连接中断时 SQLite 回滚未完成事务。指标读取失败不能把已确认提交变成重试。
最后一个会话关闭后保留最后的指标快照，不再查询已退出的所有者。

同一宿主按规范化数据库路径复用所有者，每个实例有独立事务连接。
关闭一个实例不会关闭其他实例，所有者死亡则已有实例全部失败；
重新打开必须是显式的新存储实例，不能自动重连重放。
跨进程独占租约拒绝另一个所有者；这不提供跨宿主共享连接，也不阻止绕过约定的
外部 SQLite 写入。外部写入仍由事务、revision 和 data_version 检查。

同目录首次初始化在 Rust 所有者中最多等待 5 秒，避免不同数据库恰好并发初始化时
立即失败；数据库自身的所有者租约仍立即拒绝重复所有者。
已有硬链接按现有 Unix/Windows 检查拒绝，检查不能阻止外部进程事后创建硬链接。
Windows 和 Linux 的最终运行结果仍须三平台 CI 提供，不能以本机结果替代。

## 保留的 Node 范围与下一依赖

Node 仅在此入口保留二进制定位、N-API 调用、同步兼容回调、代理身份和事件连接。
原因是现有调度与业务调用者仍依赖事务回调的属性访问、时钟和微任务顺序；
立即把回调改成异步消息会改变既有问题归属与分类结果。
后续必须把这些调用者改成 Rust 领域命令及版本化读模型，才能删除兼容代理和同步 IPC。
不能把现存循环机械搬进同步 N-API 后宣称已解决主线程停顿。

仍未完成：

- 调度 `admit`、`complete`、`reorderQueued`、`recover` 的 Rust 决策和有界读模型；
  具体约束见 [scheduler-read-model-next.md](scheduler-read-model-next.md)。
- 大请求、响应及大队列的事件循环延迟验收。协议不设固定消息总量上限，
  同步序列化和逐字段兼容 RPC 仍有开销；本批不宣称性能改善。
- 整体 Node 退出、剩余 HTTP/WS/SSE 宿主、插件和进程生命周期迁移。
- 最终安装包与三平台生命周期验收。

## 先前实验记录

下列是接入前的历史证据，不代替本批默认入口的测试：隔离临时数据库中的断开回滚、
事务冲突和失败不重放已验证；实验适配器的 160 项兼容测试和 11 项并发/混合驱动
测试通过；同库两个实例与所有者异常退出重复 10 轮通过。

早期协议中 4 MiB 准入及 1,000 条队列完成有明显同步 IPC 开销。
8 MiB 有界缓冲快路的一轮对比为现有路径 174 ms / 487 ms、隔离路径 217 ms / 837 ms；
复用所有者后的另一轮为 342 ms / 1,633 ms 与 418 ms / 3,246 ms。
两轮负载不同，不能跨轮比较绝对值；这些结果不能当作最终性能验收。

用户数据、运行服务和配置未因本批改变；本批也不修复聊天历史 OOM。
