# 编排 SQLite 独立所有者实验

状态：实验代码，尚未接入生产、尚未完成发布验证。

同一进程内不同 SQLite 实现打开同一文件后，其中一个连接关闭可能破坏另一个实现
对 WAL 锁的认知。`revision` 和 `data_version` 在该场景不构成可靠保护。实验将
编排数据库连接放进独立 Rust 进程；宿主通过标准输入和输出发送长度前缀帧，事务
始终由同一个所有者处理。传输失败时客户端终止所有者，不自动重放可能已经提交的
请求；连接中断时 SQLite 回滚未完成事务。

实验入口是 `multicc-gateway orchestration-owner`；原生接口
`RustIsolatedOrchestrationStore` 和 `experimentalOwnerBinary` 只供显式测试，
当前生产配置不会启用。隔离进程
不能阻止不遵循约定的其他进程直接写数据库，因此仍须依赖 SQLite 事务及冲突检测。

在隔离临时数据库中，所有者断开后的回滚、事务冲突和失败不重放已验证；同一宿主
中的两个实例可复用进程，各自维护事务，关闭一个不影响另一个。杀死所有者后，两
个实例均报错且未提交事务回滚。测试适配器显式切换到实验实现后，编排相关 160 项
兼容测试和 11 项并发/混合驱动测试通过；同库两个实例与所有者异常退出用例重复
10 轮通过。同一进程内仍有其他会话时，关闭连接不再执行会等待读事务的截断检查点，
最后关闭的会话继续执行原有检查点。这个结果尚不覆盖安装包与生产启动路径。
早期协议的一次本机测量中，4 MiB
准入使事件循环延迟约 153 ms，1,000 条队列完成延迟约 854 ms；切换纯流式 JSON
解析后另一次测量分别约为 826 ms 和 10.6 秒。加入 8 MiB 有界缓冲快路后，同机
单次顺序对比中，现有路径分别为 174 ms、487 ms，隔离路径为 217 ms、837 ms。
复用所有者后的另一次顺序测量分别为现有路径 342 ms、1,633 ms，实验路径
418 ms、3,246 ms。两轮机器负载不同，不能直接比较绝对数值；同轮结果仍表明
隔离路径有明显同步开销，不能当作最终验收。

接入生产前必须完成：

- 将现有编排存储接口接入独立所有者，并保证模块、网关在源码启动、桌面和各平台
  打包时来自同一版本；不得在二进制缺失时静默回退同进程 SQLite。
- 已实测同一宿主进程中按规范化数据库路径复用所有者，并为每个实例建立独立事务
  连接。不同宿主进程当前仍可能各自启动所有者，不能把
  跨进程 SQLite 锁正常工作当成全局单一所有者已完成。
- 用现有混合驱动和 claim 回归验证端到端结果；原始 SQLite 混用实验本身只用于
  证明底层风险，不能以修改其断言代替生产路径测试。
- 验证大请求、响应的兼容方案。协议改为流式读写，不再引入固定帧总量上限；
  序列化目前需要先计数再写出，大对象在同步调用中仍可能阻塞主线程，尚需基准
  与生产路径验证。
- 验证所有者异常退出、宿主崩溃、并发写、重启恢复、路径权限及 Windows 生命周期；
  事务提交结果不确定时不得自动重试。
- 完成调度准入、完成、重排和恢复的 Rust 迁移，并保持宿主事实读取的时序；所有
  写入者必须共享可校验的读模型，不能通过异步预读改变既有行为。

用户数据、服务及配置未因本实验改动；实验也不修复聊天历史 OOM。
