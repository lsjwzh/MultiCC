# 任务卡片、仓储与核心业务规则迁移到 Rust

2026-11-01。本轮将 Air 列表卡片、任务数据仓储和任务板核心规则接入 Rust。现有 HTTP/WebSocket 协议继续使用。改动保存在当前工作树，尚未提交、合并、推送或重启，运行中的服务未加载这批实现。

本轮是后端职责迁移，不作性能提升承诺。同等缓存基线下，新路径仍慢于 Node；实测及保留范围见下文。

实现位于 `native/core/src/task_domain/`、`native/core/src/task_store.rs` 及其 `rules.rs`；N-API 入口位于 `native/addon/src/task_domain.rs` 和 `task_store.rs`。两套协议版本均为 1。

Air 原有 Rust 摘要索引、分页、统计、增量重放和 ETag 继续使用。本轮接管其上游卡片生产，不以独立 SQLite 读取试点替代宿主权威会话状态。

## 缓存与异步约束

Air 输入按内容检查，包含任务板、会话事实、工作区/租约、任务壳记录与仓储 epoch；输入相同才复用 Rust 已解析结果。原地改名、线路展示名变化、权限版本和租约变化均会触发相应失效。

Rust 批量生成底稿并批量覆盖动态状态。动态状态每轮重算，运行宽限到期、执行状态和 Git/容量变化不会被底稿缓存冻结。最终卡片的复用也由 Rust 比较后返回 token 决定；Node 仅镜像 token 对应的对象。读取期间 token 被另一轮回收时，使用原请求已经取得的快照完成投影，不串入新请求的权限或卡片。

重读取、签名与批量投影使用 N-API 异步任务；宿主回调按小批次让出事件循环。异步卡片构建队列最多受理 16 个请求，溢出明确拒绝，失败后可继续受理。既有 Air 索引提交、重放与订阅的串行交接保持不变。

**同步兼容接口仍存在。** 任务壳事务回调及任务板保存仍是同步调用，原生仓储也可能在 SQLite 锁等待或文件持久化时阻塞宿主线程。这样保留了现有调用者的事务和保存确认契约；不能把本轮描述为所有数据库和文件操作都已异步。下一阶段应先将这些调用者改为显式异步提交，再整体替换，避免异步回调越出事务或提前确认保存。

## 保留的 Node 范围

Node 继续承担现有会话、AI SDK、执行、Git、历史、通知和 HTTP/WebSocket 连接的宿主流程；采集当前记录、权限和工作区容量事实，维护既有对象引用。V8 日期解析、ICU 的历史 ID 排序及宿主 UUID 继续作为兼容端口。固定日期与排序契约、迁走相应宿主权威后才可删除这些端口。

本轮迁入的是上述核心规则，不代表整个任务执行系统已重写。以下存量流程仍在 Node：

- `task-shell/runtime.js` 的壳上下文、游标与执行交接。
- `task-shell/task-actions.js` 中创建、绑定和分叉的外部执行流程，以及详情历史与会话视图组装。
- `task-shell/task-operations.js` 的轮次归属修正、队列及撤销流程。
- `task-shell/separation.js`、`independent-continue.js` 的拆分、独立续接与多步骤恢复。
- `routes/task-board.js` 中调度、分类任务编排、运行事件到写入的接线，以及 Air 的置顶/待办/忽略清单和详情资源宿主入口。

其中仍含存量校验和状态推进，不能统称为无业务逻辑的薄桥接。继续迁移时应将各流程拆成 Rust 的决策/事务和宿主外部操作端口，分别验证失败重试、幂等与恢复，不能只搬函数名后宣称完成。

新增桥接没有提供这些新核心的 Node 自动回退。旧模块或原生错误会明确失败；`MULTICC_AIR_READ_BACKEND=node` 只切换已有摘要索引，不能切回本轮迁入的卡片和仓储规则。

## 同等缓存基线性能

使用 1,000 张合成任务，旧 Node 实现与新实现均开启底稿缓存，验证最终 JSON 深度相等。热读取 31 次中位数，单卡改名刷新取 11 次中位数；双方热读均未额外构建底稿，权属读取均为 1,011 次。这个实验衡量卡片生产与传输适配，不是线上全链路收益。

| 场景 | Node | Rust |
| --- | ---: | ---: |
| 首次冷读 | 9.71 毫秒 | 45.79 毫秒 |
| 热刷新中位数 | 2.64 毫秒 | 7.67 毫秒 |
| 单卡变更刷新中位数 | 2.79 毫秒 | 20.55 毫秒 |

初版 Rust 热刷新约 33 毫秒；批量底稿/覆盖、避免全局事实逐卡复制、输入版本复用及输出 token 镜像降低了开销，但仍有明显回退。异步执行改善了工作所在的线程，不等于总计算成本下降。后续优化重点是变更输入的原生增量复用和减少跨边界数据传输，继续保留同等优化的 Node 基线；不得引用此前独立数据库试点的加速数据代替本轮结果。
