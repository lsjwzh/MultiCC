# 「🖥 屏幕」交互改造方案：幕布 + 侧栏 + 悬浮操作台

> 参考对象：用户在 iPad 上使用的远控 App（截图见任务）。它的界面是「画面占满整屏 + 右缘一列图标 + 一个可拖动的悬浮触控板/滚动条」。
> 本文是该形态落到 multicc App「屏幕」页的改造方案，先定方向、再分三期实施。
> 状态：**已实施**（P0-A/B/C 一次落地，另加「两端剪贴板互传」与「放大后精确操作」）。
> 2026-11-20 复核后又改了七处交互（见 §17），本文正文仍是方向，§17 是现行口径。
> 实施说明与偏差见文末 §14、§15、§16、§17。

## 0. 一句话结论

把「屏幕」页从**带标题栏和两条常驻工具行的页面**改成**一整块幕布**：控制入口收进右缘一列可收起的竖栏，指针精度交给一个可停靠的悬浮操作台，键盘改成按需弹出的面板。目标是把画面占比从约 74% 提到 95% 以上，同时不牺牲现有手势语义与安全横幅。

## 1. 参考对象做对的三件事

1. **画面就是页面**。没有标题栏、状态行、快捷键条；黑边即工具栏。远控的第一需求是「看清远端」，任何常驻 chrome 都是在抢画面。
2. **控制入口靠拇指，不靠屏幕顶部**。竖栏贴在右缘（单手持机时拇指自然落点），每个图标对应一个动作或一个面板，一次点击直达。
3. **精度输入是「临时工具」，不是「全局模式」**。悬浮触控板是一个可拖动的小圆盘：要用就拿手指上去，不用就搁着半透明。它不改变画面本身的手势，所以不会出现「我现在到底是触摸模式还是鼠标模式」的心智负担。

## 2. 现状（代码事实）

`app/lib/screens/remote_screen_screen.dart` 当前是竖向四段：

| 段 | 位置 | 高度（约） |
|---|---|---|
| AppBar：标题 + 重连/控制/触控板/右键/框选 5 个图标 | 969–1017 | 56 |
| 状态行：分辨率 · 模式 · 码率/延迟 · fps · 帧龄 · 错误 | 1022, 1057–1141 | 28 |
| 「唤起屏幕」按钮 + 自动解锁提示 | 1023–1046 | 44 |
| 画面舞台（InteractiveViewer + 捏合缩放 + 框选 + 侧边滚轮条） | 1049, 1252–1456 | 剩余 |
| 键盘条：文本框 + 修饰键 + 15 个键位 + 「更多」 | 1050, 1605–1684 | 86–120 |

配套件：

- `RemoteTouchController`（`app/lib/services/remote_touch_controller.dart:26`）：`direct` / `trackpad` 两档，整套手势（长按右键、按住拖拽、拖拽锁 500ms、双指滚动、双指轻点右键、光标夹在可见区、心跳保活）都在这里，纯 Dart、有单测。
- `RemoteWheelRail`（`app/lib/widgets/remote_wheel_rail.dart:28`）：滚轮条位置按「未放大的 contain 几何 + 信箱边」算，三种落点固定，用户不能挪。
- 无宿主级动作：显示桌面 / 调度中心 / 切换窗口 只能在「更多」里翻 F 键，或根本找不到。
- `hostModifier`（`remote_screen_service.dart:117, 614–617`）已经能拿到宿主是 ⌘ 还是 Ctrl；`capabilities` 还带 `platform`（`native/remote/src/host.rs:91–101`），但 App 目前只读了 `modifier` 和 `streams`。

## 3. 诊断：五个具体问题

1. **画面被长期压缩**。iPhone 390×844 上 56+28+44+86≈214，画面只剩约 74%；iPad 横屏同理。远控最贵的资源是像素，这里白送掉四分之一。
2. **入口分居两端**。控制/触控板/右键在顶部 AppBar，键盘和修饰键在底部，单手拿手机时总有一半要点两次才够得着。
3. **触控板是全局模式**。切到触控板后，画面上的单指不再点哪打哪（`remote_screen_screen.dart:589–608, 698–720`），而且这个模式藏在顶部图标里、状态只写在一行 11.5px 的小字里。误切后最常见的反馈是「点了没反应」。
4. **滚动条位置不可控**。三条固定落点规则里，全屏铺满时它浮在画面右缘正中间，盖住的往往正是远端窗口的滚动条位置；用户没法把它挪开或收起来。
5. **常驻但低频的东西占了常驻的位置**。「唤起屏幕」是偶发动作，却和画面平分一行；状态读数（fps/码率）每秒变化，却一直占一条；键盘条在只看不操作时也要占 86px。

## 4. 目标形态

三层，自底向上：

```
┌───────────────────────────────────────────────┬──┐
│                                               │⌃ │  ← 侧栏（可收起为 8dp 触条）
│                                               │◉ │     返回 / 指针 / 键盘
│              幕 布（画面 100% 铺底）            │⌨ │     宿主 / 视图 / 状态
│                                               │▤ │
│         ┌──────── 顶部 HUD 胶囊 ────────┐      │⤢ │
│         │ 流畅 · 38fps · 1.8Mbps · 中继 │      │ⓘ │
│         └──────────────────────────────┘      │  │
│                                               │  │
│                        ╭──────────╮           │  │
│                        │  ╭────╮  │           │  │  ← 悬浮操作台（可拖、可停靠四角）
│                        │  │ ▭  │  │           │  │     圆盘触控板 + 滚轮胶囊
│                        │  ╰────╯  │           │  │
│                        ╰──────────╯           │  │
└───────────────────────────────────────────────┴──┘
```

- **幕布**：`Scaffold` 不再挂 AppBar，`body` 直接是舞台（安全区内），进入页面时 `SystemChrome.setEnabledSystemUIMode(immersiveSticky)`，退出恢复。画面 contain 铺满（与现在同一套 `InteractiveViewer` 数学，`1354–1456` 原样保留）。
- **侧栏**（新）：右缘 48dp 宽浮层，6 个 44dp 图标，5s 无操作收成 8dp 触条（图标淡化到 0.35），点触条展开。默认右侧，可切左侧并记住（单手习惯）。
- **悬浮操作台**（新）：直径 148dp 的圆盘 + 紧贴的 34×150 滚轮胶囊；可拖到任意位置，松手吸附到四角（含安全区）。闲置 3s 后整体 0.35 透明度，摸一下恢复。点侧栏「指针」显隐。
- **键盘面板**（新）：底部 sheet（默认 42% 高，可拖到 70%），内部是文本框（自动聚焦、走系统 IME）+ 紧凑键位网格；修饰键锁定时，收起 sheet 后底部浮出一条 32dp 的修饰键条，随时看到「⌘ 还按着」。
- **HUD**：状态读数变成顶部居中的小胶囊，出帧/报错/切模式时出现，3s 后淡出；点侧栏「状态」可唤出完整面板（分辨率、码率、延迟、路径、帧龄、错误原文）。
- **保留不动**：权限横幅（`_permBanner`）、急停横幅（`_haltBanner`）、框选、捏合缩放、坐标映射、RFB/H.264 两条通道、Rust 侧协议。

## 6. 交互规格

### 侧栏

| 操作 | 结果 |
|---|---|
| 单击图标 | 打开对应面板 / 执行动作（宿主动作直接发和弦） |
| 长按 350ms | 浮出名称气泡 + 触觉，不改变状态 |
| 5s 无交互 | 收成 8dp 触条；展开态下若面板打开则保持 |
| 点触条 | 展开，2.5s 后自动收（面板打开时保持） |
| 左右互换 | 状态面板里的「侧栏靠左」开关，`SharedPreferences` 记住 |
| 急停中 | 整宽红横幅 + 「解除急停」按钮；侧栏「更多」项变红（文档原先写「侧栏只保留两项」，实现没这么做，而且整宽横幅比红侧栏更显眼 —— 以实现为准） |

### 悬浮操作台

| 手势 | 结果 |
|---|---|
| 单指拖动盘面 | 光标相对移动（带加速度，`motionGain` 决定灵敏度） |
| 轻点盘面 | 左键单击（⌘/⇧ 一次性的照常生效） |
| 按住 350ms 后拖 | 进入拖拽；松手后 500ms 内再落继续同一段拖拽（复用现有语义） |
| 双指轻点 | 右键 |
| 双指上下滑 | 滚动（`direct` 模式下也可用，因为操作台本身就是 trackpad 实例） |
| 拖滚轮胶囊握把 / 点箭头 | 连续滚 / 一格；按住箭头连发 |
| 拖圆盘底座 | 移动操作台，松手吸附四角；点侧栏「指针」收起 |

### 幕布（保持现有语义，`remote_touch_controller.dart:8–25`）

| 手势 | 结果 |
|---|---|
| 单指轻点 | 左键单击（`_rightOnce` 点亮时右键） |
| 单指按住 500ms 不动 | 右键（触觉反馈） |
| 单指拖动 | 左键拖拽（按在最初落点） |
| 双指捏合 / 平移 | 缩放 + 平移（放大后手指位移按缩放比变细） |
| 双击 | 看模式：2.5× 放大 / 放大态复位 |
| 框选态 | 独占指针画框，松手裁剪；此时隐藏侧栏与操作台 |

### 键盘面板

| 操作 | 结果 |
|---|---|
| 点侧栏「键盘」 | 弹出 sheet，文本框自动聚焦，系统 IME 直接打字（中文可用） |
| 拖动顶部把手 | 42% ↔ 70% |
| 收起 sheet | 若有修饰键处于一次性/锁定，底部浮出 32dp 修饰键条 |
| 面板内键位 | 与现有 `_keyBarSpecs` / `_moreKeySpecs` 同一张表，不再有「更多」二级折叠（网格直接铺开） |

## 7. 关键实现细节

1. **两个 controller，不是一个模式开关。** 舞台永远 `direct`；操作台单独一个 `RemoteTouchController(mode: trackpad)`。两者都只调 `_svc.source.pointerEvent` / `_svc.inputOp`，互不知道对方存在。删除 `_toggleTrackpad`，能一次性消掉「模式错乱」这一类反馈。
2. **`motionGain` 是唯一需要改的算法。** 现有 `_padMove` 的增益是 `source.width / display.width / viewScale × 加速度`（`remote_touch_controller.dart:341–344`），对「画面 = 触控面」成立，对 148dp 的圆盘不成立（会放大 20 倍）。加一个可选 `motionGain`：非 0 时直接用它，0 时走原公式，原有用例一字不改。
3. **手势不打架靠区域归属，不靠优先级。** 侧栏、操作台、键盘 sheet 都是独立 `Positioned` 的 opaque 命中区，画面 Listener 收不到落在它们上面的指针；框选层按现有做法整体独占（`1407–1439`）。
4. **坐标域不变。** 操作台喂给 controller 的是视口 `global` 坐标（trackpad 公式只用位移），输出的仍是源图像素；`visible` 仍按当前缩放矩阵算（`723–735`），所以把画面放大后操作台光标照样只在看得见的块里走。
5. **键盘 inset。** `resizeToAvoidBottomInset: true`，sheet 用 `showModalBottomSheet(isScrollControlled: true)` 或自绘 `AnimatedPositioned`；弹出时操作台自动上移到键盘上沿，避免被盖住。
6. **沉浸式进入/退出**：`initState` 设 `immersiveSticky`，`dispose` 恢复 `edgeToEdge`；不支持的平台（`_unsupportedScaffold`）不进入沉浸式。
7. **偏好**：`remote_rail_side`（right/left）、`remote_pod_pos`（四角）、`remote_pod_visible`、`remote_pod_gain`（0.8/1.0/1.3 三档，放状态面板）。旧键 `remote_screen_trackpad` 迁移为「启动时显示操作台」。

## 8. 边界与状态

| 状态 | 表现 |
|---|---|
| 兼容模式（JPEG fallback） | 侧栏与操作台照常可用；滚动走 HTTP `_drainScroll`，与现在一致 |
| 未取到操作权 | 侧栏只剩「指针（禁用）」「状态」；HUD 写「只看模式」，点一下申请操作 |
| 权限未通过 | 权限横幅整宽置顶（不改），侧栏可用但操作项禁用 |
| 急停（Esc） | 红色横幅 + 侧栏变红，操作台收起 |
| 断线重连 | 侧栏「状态」转圈；输入禁用；重连后恢复原停靠位 |
| 画面全黑/无帧 | HUD 转琥珀色「N 秒无新帧」，点状态面板看错误码（现有 `_frameAgeShown` 逻辑保留） |
| 框选态 | 侧栏/操作台隐藏，只留「取消」与缩放徽标 |
| 平板横屏 / 手机竖屏 | 同一套布局；侧栏贴实际安全区内缘；操作台默认停在右下（右手） |

## 9. 分三期落地

**P0-A 幕布骨架（可单独上线）**
去掉 AppBar、状态行、「唤起屏幕」行；加侧栏（返回/指针/键盘/宿主/视图/状态 六项，其中指针先空着）、HUD、状态面板；**键盘条暂时原样保留在幕布下方**，保证输入能力不倒退。
验收：画面占比 ≥ 95%；旧键盘与框选/缩放测试全绿；唤醒入口在状态面板里可用。

**P0-B 悬浮操作台**
`RemoteControlPod` + `motionGain` + 双 controller 接线；删除全局触控板模式；画面侧滚轮条改为「操作台隐藏时才出现」。
验收：舞台单指永远直接操作；操作台拖动/轻点/双指/拖拽锁全部动作在真机可用；滚轮只有一套可见 UI。

**P0-C 键盘面板与宿主动作**
`RemoteKeySheet` + 修饰键浮条 + 宿主三动作 + i18n；删除常驻键盘条，改 6 个既有测试用例。
验收：中文 IME 输入、⇧ 一次性/⌘ 锁定、F1/F12/方向键连发全部可用；「显示桌面」「调度中心」「切换窗口」各一次点击生效。

**P1（另议）**
侧栏边缘滑出手势、单手模式（侧栏+操作台整体下移）、操作台灵敏度滑杆、Web 版对齐、iPad 外接指针 hover、多显示器选屏。

## 11. 风险与取舍

| 风险 | 处置 |
|---|---|
| 幕布化后「返回」不明显 | 侧栏第一项固定返回 + 系统返回手势；HUD 左侧留 20dp 不遮挡系统手势区 |
| 图标语义要靠猜 | 长按气泡 + 首次进入一次性引导（3 张提示卡，可跳过） |
| 半透明浮层仍可能挡住远端窗口右下角 | 收起态 8dp、闲置 0.35 透明度、可拖到左下、可整体隐藏（状态面板开关） |
| 删除全局触控板模式会让老用户不习惯 | 操作台默认显示在右下角，视觉上就是「触控板在那」；偏好里保留「启动即显示」 |
| 两个 controller 同时存在导致光标标记重复 | 只有操作台实例挂 `onCursor`；舞台实例在 trackpad 语义下不产生光标标记 |
| P0-C 改 6 个测试有回归面 | 先加 `openKeySheet` 辅助再批量替换，逐用例跑 |

## 12. 需要拍板的三个问题

1. **范围**：只改 App（Web 版 `public/chat-remote-screen.js` 保持现状），还是 App 先做、Web 随后对齐？
2. **侧栏默认侧**：横竖屏都默认右侧（右手），还是竖屏右侧、横屏左侧（避免压住远端窗口的控制按钮）？
3. **落地节奏**：按 P0-A → B → C 三期分别可上线，还是一次做完再一起验证？

## 13. 明确不做

- 不做全屏九宫格虚拟键盘（系统 IME 已够用，自绘键盘会丢中文候选）。
- 不做远端多显示器/选屏（需要 Rust 侧新增能力，另立方案）。
- 不做远端鼠标指针形态同步（RFB 有 `SetCursor`，但 H.264 通道没有，两通道行为会不一致）。
- 不新增输入 op；宿主动作只用现有 `press` 和弦。

## 14. 剪贴板双向透传（本轮追加）

目标：手机上复制的文字能直接粘进远端；远端复制的文字能一键带回手机。

**协议**：新增两个桌面 Agent op（`scripts/macos-agent/MultiCCAgent.swift`），只允许
`session: "remote-screen"`：

| op | 结果 |
|---|---|
| `clipboard-read` | `{ok, text, length, truncated?}`，最多 200000 个 UTF-16 码元 |
| `clipboard-write` | `{ok, length}`；覆盖系统剪贴板文本 |

**服务端**（Rust `multicc-remote`，`native/remote/src/routes.rs`）：
`GET /api/remote-screen/clipboard` 读、`POST` 写，正文上限 200000 码元；超长读取由服务端
截断并带 `truncated`。老 Agent 回 `unknown op: …` 时收敛成 `clipboard-unavailable`，
文案指向「更新桌面 Agent」，不让裸字符串漏给用户。

**App**：侧栏「剪贴板」面板三个动作 ——

1. 复制远端剪贴板到本机（读到就写手机剪贴板，Toast 报字数）；
2. 把本机剪贴板写入远端（之后用户自己按 ⌘V）；
3. 写入并粘贴到远端（写完自动发一次 ⌘V 和弦）。

**安全与边界**：

- **只在点按时搬运**，没有轮询、没有监听、没有后台同步：剪贴板里常有密码和验证码。
- 不做 `type` 兜底自动降级：直接键入和「粘贴」在远端应用里语义不同（富文本、多行、
  触发搜索等），静默换一种会让用户以为粘贴成功。
- Web 版暂不出入口，但路由和错误码已经是共享契约。

## 15. 放大可视区域之后的精确操作（本轮追加）

双指放大本身是旧能力，缺的是「放大之后怎么点得准」：

1. **舞台永远直接触摸**：放大后单指仍是「点哪打哪」，双指只管缩放与平移
   （`_viewPointers` 少于两指时 InteractiveViewer 的变换被写回起点）。
2. **取景器（放大镜）**：放大态下按住时，手指上方 96dp 的圆窗按 2.4× 显示指针附近
   的源画面，并画十字准星。手指不再挡住目标，落点误差从「一个指腹」降到几个像素。
   可在「视图」面板关掉。
3. **边缘自动平移**：拖拽到视口边缘时画面朝那一侧推（原有逻辑，改为对操作台也生效）。
4. **视图面板**：适应 / 2× / 3× / 框选放大，配合右下角百分比徽标复位。
5. **操作台灵敏度**：慢 / 标准 / 快三档（0.7 / 1.0 / 1.4 源像素每逻辑像素），
   用 `RemoteTouchController.motionGain` 覆盖「按舞台尺寸换算」的旧公式。

## 16. 实施偏差与遗留

- 侧栏实际 7 项（返回 / 指针 / 键盘 / 宿主 / 视图 / 剪贴板 / 状态）；短屏（横屏手机）
  用 `FittedBox.scaleDown` 等比缩小，而不是溢出。
- 操作台带拖动把手（顶部 20dp），圆盘本身只发指针事件 —— 移动工具和操作工具分开，
  避免「想挪操作台却点了一下远端」。
- 常驻键盘条已删除，`remote_screen_gestures_test.dart` 的键位用例改为先打开面板；
  新增 `remote_screen_shell_test.dart`（幕布 / 侧栏 / 面板 / 剪贴板 / 短屏）与
  `remote_host_actions_test.dart`。
- 已知环境问题（与本改动无关）：`scripts/ensure-source-rust.js` 把 `--out` 传成
  `dirname(addon)`，而 `build-rust-kernels.js` 会再拼一层 `<platform>-<arch>`，源码
  启动/端到端测试在缓存目录里找不到前门二进制。运行时用现成二进制绕过，未在本轮修改。

## 17. 复核后的七处返工（2026-11-20）

复核的判断是：骨架（幕布 + 侧栏 + 悬浮操作台 + 按需键盘）站得住，但有两处把参考 App
的妥协当成了设计原则照搬，另有五处落地结果和本文自己的验收标准或平台习惯不一致。

### 17.1 键盘面板改成非模态（最大的一处）

原实现用 `showModalBottomSheet(barrierColor: black26)`：键盘开着时画面被压暗、而且
**完全点不动**，点下去只是关掉面板。但远控打字的真实循环是「看屏 → 点远端输入框 →
打字 → 再点另一个框」，旧那条常驻键盘条虽然吃 86dp，却从不挡这个循环 —— 所以这是
相对旧版的功能退步。§7-5 本来写的是「`showModalBottomSheet` **或**自绘
`AnimatedPositioned`」，实现挑了省事的那条。

现在面板是 `Stack` 里的一层 `Positioned`，舞台按面板高度**让出**而不是被盖住
（`bottom: keyTaken`）。因为舞台的 contain 几何重算了一遍，「点哪打哪」的坐标映射
自动保持正确，不需要任何偏移补偿。面板高度口径由 `remoteKeyPanelHeight()` 这一处给
出，页面和组件共用，防止两边漂开。

面板也瘦了一圈：标题行并进输入行，键位网格默认收起（常用键横排一行，就是旧键盘条的
位置），要找 F 键 / Home / End 才点开。收起态本体 100dp，展开 288dp。

### 17.2 舞台双指直接滚远端，滚轮胶囊整条删掉

`remote_touch_controller.dart` 原先把 `mode == direct` 一刀切成捏合，于是画面上两指
平行滑动永远是缩放 / 平移，想滚远端只能把手指挪到 148dp 的圆盘上，或者去拖那条
34×150 的滚轮胶囊 —— 手机上没人用滚动条滚页面。而「平行滑动 vs 捏合」的判别逻辑
控制器里本来就写好了，只是 direct 档被排除在外。

放开之后：未放大时双指滑动 = 滚远端，捏合 = 缩放，放大之后双指全部让给画面（此时
画面有地方可挪）。配套两件事：

- **滚轮锚点**：direct 档根本不维护 `cursor`（它停在 (0,0) 或上一次触控板的位置），
  拿它当锚点会滚错窗口。新增 `_scrollAnchor()`：direct 档用**两指重心**映射到源画面，
  也就是「滚我手指底下那个东西」，比触控板那套「滚虚拟光标所在处」更直觉。
- **兼容模式**：JPEG 回退没有滚轮通道，滚轮掩码原先被 `_emitPointer` 静默丢掉（只有
  滚轮条走 HTTP `scroll`）。现在掩码 0x08/0x10 合并进 `_wheelNotch` 的同一条路。

于是 `remote_wheel_rail.dart` 连同它的测试一起删除，浮层面积少掉约四成，操作台缩成
一个纯圆盘 + 拖动把手。代价：只能用一根手指的用户失去滚动手势（圆盘上两指仍可滚）。

### 17.3 侧栏显隐从计时器改成意图驱动

原规则是「6 秒无操作收成 10dp 触条」。计时器在替用户做决定：读屏思考时它消失，要用时
它不回来。新规则是视频播放器那套 —— **手指落到画面上就收，抬手静止 1.2s 就回**；
计时器只服务「回来」这一侧（出现比消失便宜）。触条本身也修了两处：

- 画 10dp、**摸 44dp**（透明外扩）。原先命中区就是 10dp，和 §5 自己写的「命中区
  ≥44dp」验收冲突；收起之后要在动着的画面边缘戳一条 10dp 的线才能回来。
- 触条认轻点也认**往里划**（看位移不看甩动速度，慢慢拖也开）。只在收起态挂这个手势，
  画面上的拖拽不受影响。

### 17.4 侧栏 7 项降到 4 项，面板按设备换落点

七个等权图标是菜单不是工具栏，而且横屏手机放不下，只能靠 `FittedBox` 等比缩到约
36dp（iPhone 14 Pro 横屏实算：可用 260dp / 内容 318dp = 0.82×）—— 又一次低于 44dp。

按真实频次分：键盘高频、指针是开关、返回一次，其余四项（视图 / 剪贴板 / 宿主 /
状态）合起来就是一个「工具」对象，收进「更多」的一个滚动面板，四节按频次排。四项
44dp 在任何手机尺寸下原尺寸都放得下（横屏可用 260dp / 内容 184dp）。

面板落点也改了：原先一律锚在**右上角**（`top: safe.top + 56`），面板里的按钮全落在
单手拇指到不了的那块。现在手机走**底部 sheet**（带遮罩、点外面收起，和键盘面板同一个
方向），平板才走贴着侧栏的锚定浮层（平板哪儿都够得到，小卡片不挡画面，不加遮罩）。

### 17.5 「指针」不再一个图标两种含义

原 `_onRail('pointer')` 在只看模式下是「取操作权」、有操作权时是「操作台开关」——
本方案的立意正是消灭模式歧义，这里却造了一个随状态改变语义的按钮。

「只看 / 操作」是**状态**，所以开关长在状态上：只看模式下 HUD 常驻（不随 4 秒淡出
消失）并写「只看模式 · 点此申请操作」，点一下就是申请操作权。侧栏「指针」只管操作台，
而且只在有操作权时出现。

### 17.6 剪贴板三个按钮收成两个

「写入远端不粘贴」是「写入并粘贴」的弱版，没人能说清什么时候该用它。现在主按钮是
「粘贴到远端（⌘V）」，弱版改成它的**长按**；另一个是「取回远端剪贴板」。

更重要的是入口位置：粘贴几乎总发生在打字的上下文里，所以键盘面板的输入框旁边直接有
一个「粘贴」键，不必绕回侧栏第四个图标后面的面板。

### 17.7 取景器倍率改成相对舞台

`_LoupePainter` 原先是固定 2.4 逻辑像素/源像素。手机上画面贴合约 0.26，确实放大约
九倍；但 iPad 横屏贴合约 0.68，用户再 3× 放大后舞台已经约 2.03，取景器只比画面本身
清楚不到两成，等于白开一个窗挡视线。改成 `max(2.4, 舞台倍率 × 2)`。另外靠近上缘时
**翻到手指下方**，而不是只做 `clamp`（夹取会把窗口压到目标自己身上）。

### 17.8 顺带修掉的三件小事

- **两处硬编码中文绕过 i18n**：灵敏度档位「慢 / 标准 / 快」和缩放徽标「全屏 · N%」。
- **英文目录补齐**：这一页新增的键原先只进了 zh.json。`en.json` 按设计是子集（缺键
  回落 zh），但非中文区默认语言是 en，于是英文用户看到的是一整排中文图标提示。现在
  这一页的控制面（侧栏 / HUD / 面板 / 剪贴板 / 键盘面板 / 宿主动作）en 全部补齐。
- **首次引导**：§11 许诺的「3 张提示卡」没做，也不建议做（没人看）。换成**首次进入
  侧栏带文字标签、三秒后自己收成图标** —— 用一次演示代替说明书。

### 17.9 剪贴板截断的单位（Rust + Swift）

契约写的是「上限 20 万个 UTF-16 码元」，但读路径上**判定用码元、截断用字符**：
`native/remote/src/routes.rs` 的 `chars().take(200_000)` 与 Agent 的
`String.prefix(200_000)`（后者数的还是字形簇）。一段 20 万个 emoji（40 万码元）会被
判定超限、却一个字符都切不掉，于是带着 `truncated:true` 原样透传 —— 上限等于没有。
写路径按码元严格拒绝，两边口径不一致。

两侧都改成按码元截断、切点落在字符（Swift 是字形簇）边界上，宁可少一两个码元也不切出
半个代理对；`length` 也统一成码元数。Agent 源码改了就要 `node src/macos-agent-build.js
bump`，否则 `tests/test-macos-agent.js` 的指纹断言会红，别的 MultiCC 副本也认不出新版。

## 18. 远控链路的 Node 残留与迁移前置件（未做）

`src/remote-screen-rust.js`（608 行）自己的文件头就写了退出条件：「等全站鉴权和 WS
路由也迁进 Rust 进程（或 Rust 直接接管 Node 的监听端口）时，这一层连同 server.js 里的
mount 一起删除」。现状盘点：

| 它还在做什么 | 迁到前门要什么 |
|---|---|
| 懒启动 + 看护 `multicc-remote`（退避 1/2/4…30s、稳定 60s 清零、stdin EOF 收尾、就绪行解析 10s 超时） | 前门已经在用同一套机制看护 Node，需要抽成「第二个被看护子进程」 |
| 4 条 HTTP 路由原样转发 + `x-multicc-remote-secret` 注入 + 不可用时的收敛应答 | 前门已有 L7 转发与原生路由骨架（`docs/gateway.md` §9 配方） |
| `/ws/remote-screen` 逐帧转发 + 背压（64KB/16KB 水位、15ms 轮询）+ 关闭码净化 | 前门已终结 `/ws/chat`、`/ws/machines` 的升级（§64、§65），可复用 |
| ~~电源同意头~~（`getPowerPreferences().read(true)` 或 `createPowerd().readIntent()`） | **已解除（8a）**：`native/remote/src/power.rs` 直接读两个开关，头与 Node 侧计算已一起删除 |

所以这不是一次提交的事：按仓库自己的配方（搬路由 = 同提交删 Node + 差分逐字节），
顺序是 ①电源同意读取迁 Rust（**8a，已做**）→ ②前门接管被看护子进程（8b）→ ③4 条
HTTP + 1 条 WS 同提交搬走并删 Node + 跑差分（8b/8c）→ ④删 `src/remote-screen.js` 与
`server.js` 的 mount（8c）。半途停下会让远控整条不可用，所以 8b、8c 必须各自整步落地。

### 18.1 8a 做了什么

- 新增 `native/remote/src/power.rs`：`Power::consent()` 返回 `Allowed / Denied / Unreadable`，
  规则与迁移前 Node 完全一致（`read(true) || readIntent() === 'on'`，开关为真短路）。
- `wake.rs` 的 `get/post` 不再收 `HeaderMap`；同意值每个请求算一次，POST 的前后两次读状态
  共用同一个值，避免中途拨开关让一次请求自相矛盾。
- `AppState` 多一个 `power` 字段；`with_power` 供测试指到临时文件，否则用例会读开发机真实设置。
- Node 侧删掉 `deps.powerConsent`、`powerConsentHeader()` 与对 `host-power-services` /
  `powerd` 的依赖；`tests/test-remote-screen.js` 里那条断言改成「唤屏请求不带同意头」，防止回长。
- 8a 当时保留了两个写入口。网页电源设置路由通过 `src/host-power-services.js` 写设置，
  `plugins/utils/macos-power.js` 通过 `src/powerd.js` 写关盖运行意图。当时更改「允许自动解锁」
  的语义，需要同时更新 Node 的电源模块和 Rust 的 `power.rs`。

2026-11-27 补记：电源写路径已迁入 Rust，`plugins/utils/macos-power.js` 与 `src/powerd.js`
均已删除。电源守护进程测试直接调用 addon 的 `systemPowerDaemon` 和 `powerDaemon`。
