# 多电脑管理：实现与使用

网页与 App 使用相同层级：控制台 → 多电脑 → 某台电脑 → 目录或电脑设置。

## 入口与操作对象

网页在控制台的「任务 / 目录」右侧增加「多电脑」。每台电脑是一枚子标签，下方显示目录和电脑设置入口。远程目录及设置复用现有功能，外层侧栏继续属于入口电脑。

App 保留「控制台 / 定时任务 / 工作目录」底部导航，在控制台内部增加多电脑入口。远程目录使用独立连接上下文；电脑设置使用独立页面，分类与配置详情之间可以逐层返回。退出远程页面后保留此前选择的电脑。

远程页面持续显示操作与保存目标，主要配置保存按钮显示「保存到 电脑名」。网络中断、授权失效或电脑不存在时显示错误，禁止回退到入口电脑执行请求。

## 连接一台电脑

1. 入口电脑与目标电脑都安装包含本功能的 MultiCC 及配套 Rust 原生组件，并由用户手动重启服务。
2. 为目标电脑设置 MultiCC 访问密码，确认入口电脑能够访问其地址。仅输入协议、主机与端口，例如 `https://computer.example`；使用自己实际可达的内网、隧道或外网入口。
3. 在「控制台 → 多电脑 → 添加电脑」填写名称、地址和目标电脑访问密码，点击「验证并连接」。密码只在产品连接表单输入，不要发到聊天中。
4. 选择电脑子标签，浏览其目录，或进入电脑设置。

访问密码用于本次验证，后续请求使用可单独撤销的电脑授权。手机和网页不保存远程访问密码或持久授权；入口服务私密保存出站授权，目标服务只保存入站授权的摘要。电脑连接允许管理目标电脑的任务与配置，请仅连接自己管理的电脑。

## 配置存放位置

| 作用范围 | 配置示例 | 存放与入口 |
| --- | --- | --- |
| 使用端 | 语言、字号、展示方式、通知偏好 | 当前手机或浏览器的偏好，仍在外层设置管理 |
| 电脑 | 模型账号、CLI、保险箱、隧道、消息桥接、主机状态 | 目标电脑服务，进入该电脑的设置管理 |
| 目录 | 工作路径、目录相关配置 | 所属电脑中的对应目录 |
| 任务 | 模型选择、执行配置、草稿与运行缓存 | 任务所属电脑；客户端缓存以电脑标识隔离 |

配置按作用范围独立保存，不会因切换电脑而复制账号或保险箱，也不会改变外层侧栏设置的操作对象。同名任务和目录在不同电脑上的缓存相互隔离。

远程聊天中的图片、消息操作、标注存入保险箱与交接包都沿用当前电脑的上下文。文件外开会先经过入口网页的既有登录交换，再访问带电脑标识的下载接口，下载地址不携带长效凭据。

临时产物网页、插件页面与已发布服务使用目标电脑自己的地址打开，不将任意远程网页转成入口电脑同源页面。手机或浏览器需能直接访问目标地址，受保护服务还需在目标地址登录。

## 重新连接、移除与撤销

- 重新连接会检查电脑身份；地址指向另一台电脑时应单独添加，不能悄悄替换原来的电脑。
- 再次连接同一台电脑会更新原连接并轮换授权，不产生重复电脑。
- 「移除连接」会尝试撤销目标电脑上的授权，再移除入口处的连接记录。若目标离线，本地移除仍会完成，页面提示到目标电脑手动撤销旧授权。
- 每台电脑自己的「多电脑 → 访问授权」显示哪些入口电脑能访问自己，可逐项撤销。撤销后后续请求被拒绝，已有实时连接被关闭。
- 电脑身份、连接与授权存放于服务数据目录的 `machines.json`；Unix 系统文件权限为 0600。它属于服务私密数据，不应提交到 Git 或放入可公开分享的文件中。

## 实现边界

电脑身份、授权交换与撤销、注册表读写、地址校验、固定 DNS、远程 HTTP 请求及增量事件流均在 Rust 中实现。模块不可用时返回明确错误，不使用 Node.js 业务实现兜底。

Node.js 仅保留现有 Express 请求/响应对象、原生模块调用和 `ws` SDK 的桥接。原因是现有服务仍由这些 SDK 承载，立即替换整个服务宿主会扩大本次变更范围；桥接不持久化凭据、不自行选择目标地址、不承载注册表和授权核心。后续 Rust HTTP/WebSocket 宿主具备替代接口并通过相同契约测试后，可移除这层适配。

电脑访问密码交换、嵌套电脑管理等接口不开放给普通远程代理；HTTP、实时连接与事件流分别有路径、大小、超时或背压限制。

## 限制与安全须知

- 配对授权等同于目标电脑的完整管理权：可管理任务与配置、读取文件、重启服务。授权不会过期，请只连接自己管理的电脑。
- 入口电脑离线或服务数据丢失时，无法从入口侧撤销授权，需要到目标电脑的「多电脑 → 访问授权」列表里手动撤销。
- 使用 `http://` 地址时，访问密码与电脑授权以明文传输；跨公网访问请一律使用 `https://`。
- 暂不支持自签或不受信任的 HTTPS 证书；请使用受信任证书、Tailscale 等可信隧道，或局域网内的 `http://` 地址。
- 经电脑代理的单个文件或请求体上限为 48MB；超过上限的文件请在目标电脑上直接打开或下载。
- 远程的 `/artifacts`、`/services`、`/plugins` 链接直接打开目标电脑的地址，需要在浏览器中登录过目标电脑。
- 浏览器发出的跨站请求（`Sec-Fetch-Site: cross-site`）会被多电脑接口拒绝；App 与服务端之间的请求不受影响。

- 双服务集成 3 项测试通过，覆盖远程写入隔离、二进制上传、增量事件流、实时连接桥接、撤销授权、离线错误及身份核对；原生组件缺失时明确拒绝操作。
- 网页真实控制台浏览器测试通过，覆盖入口侧栏不变、远程请求与草稿隔离、刷新保留远程页面、设置返回、正确的保存目标及 390 像素窄屏。
- 既有认证与实时连接路由 40 项测试通过，词典检查通过。
- Flutter 电脑作用域、实时连接票据、移动导航、控制台、消息气泡、交接包与标注格式共 79 项测试通过；改动文件静态分析通过。新增用例核对远程聊天图片与交接包确实请求所选电脑。
- 源码行数、运行时写入清单、测试分层及补丁空白检查通过。

以上是本地自动化验证，并非真实多设备发布或 iOS / Android 真机验收。没有自动重启正在运行的 MultiCC，也没有构建、签名或发布新的 App 安装包。

代码进入实际运行版本后，两台电脑需安装包含新导出接口的 Rust 原生模块（开发环境使用项目既有 `npm run build:rust` 构建入口），并由用户手动重启各自服务；网页刷新加载新脚本。App 需要重新构建并安装后才能使用新增界面。
