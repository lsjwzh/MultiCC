# Air 摘要读模型默认使用 Rust（2026-10-24）

任务列表/Air 的摘要索引、筛选分页、统计、引导集合、增量重放与旧版完整快照序列化现在默认由 Rust 执行。Web 与 App 继续使用原有 HTTP/WS 协议。源码变更需用户手动重启 MultiCC 后加载；本轮没有重启运行中的服务。

此前的[首轮读取试点](rust-task-read-model-pilot-2026-10-24.md)与[热路径、Air 契约对照](rust-task-read-model-hot-air-2026-10-24.md)保留为阶段记录。用户在本轮明确授权接入 Rust 并提交、合并，因此此前“继续隔离、不接入生产”的决定已由本轮接入取代。

## 迁移范围与保留端口

Rust 位于 native/core/src/task_read_model/，通过异步 RustTaskReadModel 原生类接入。Air 索引持有完整摘要、元数据、排序、查询缓存、epoch/revision、删除标记与有界重放历史。

现有宿主仍负责调用任务板及任务壳的权威入口，生成可见卡片，以及提供会话运行状态、权限、派发宽限、Git 缓存和容量结果。这部分依赖已有宿主对象及运行时端口，立即改写会扩大权属与状态风险，因此作为迁移桥接保留。没有把缺少生命周期字段的数据库任务壳直接当作完整 Air 卡片。

新增 Node 代码仅承担 JSON/N-API 调用、FIFO 排队、HTTP/WS 适配、socket 生命周期和必要的历史 ID ICU 排序。它不新增任务筛选、计数、缓存或重放业务规则。固定 locale/Unicode 契约后可移除 ICU 适配；宿主权威入口形成 Rust 端口并通过对照后，再逐项迁移剩余卡片生成规则。

独立 SQLite 直接读取试点仍是可调用的只读工具，未替代上述权威卡片生成入口。此前该试点的冷读加速数据不能直接代表本轮生产接入路径。此前实验也证明热缓存请求 Rust 慢于 Node；这次切换依照用户授权推进后端迁移，不作全面性能提升承诺。

## 默认值与应急回退

- 未配置 MULTICC_AIR_READ_BACKEND 时使用 rust。
- 仅显式配置 MULTICC_AIR_READ_BACKEND=node 时使用保留的 Node 索引。
- 未知配置直接拒绝；Rust 模块缺失、接口不符或运行失败不会自动降级为 Node。
- 配置或代码变更都需要用户手动重启生效。

源码启动的原生产物预检现在要求 taskReadModelProtocolVersion=1，并实际执行 Air open、publish、serialized 和 close。源码指纹缓存会随 Rust 源码变化重新构建；安装包需包含对应平台的新模块。旧模块不能通过新版预检。

## 异步 HTTP/WS 交接

一个宿主仍只有一个卡片生产者，构建在索引交接通道之外执行。索引提交并向现有客户端推送，与“读取重放窗口并订阅实时事件”共用一个串行通道：

1. 变更若先于重连交接提交，重放包含该变更。
2. 变更若晚于重连交接提交，订阅已建立，实时推送包含该变更。
3. 两段异步原生调用之间不会插入另一份索引提交，避免漏帧。

读取等待上限默认 64，可配置范围 1–256；满载返回 503/air_busy。生产者保留一个提交位置，避免持续读取导致刷新无法排队。失败不会污染后续队列。关闭时停止调度、关闭已订阅及正在交接的 socket，等待已受理工作结束后释放原生模型。

Rust publish 一次返回提交事件及所需各 dayStart 的统计；sync 一次返回同一版本的重放与统计。因此事件游标与计数不会来自不同索引版本。Node 仅添加 checkedAt/degraded 等宿主传输状态。

旧版 GET /api/air 通过异步 serialized 取得 Rust 缓存的完整 JSON 和 SHA-1 弱 ETag，继续支持条件请求与 304。序列化正文由 Rust 生成，JSON 属性顺序可能与旧 Node 不同；ETag 依据实际发送的正文计算，语义及同一版本稳定性经过验证。

- 原生回归：143/143，通过且零跳过。
- 任务主流程：363/363，通过且零跳过。
- 新增交接测试覆盖：重放读取后到订阅前发生更新、原生提交后到推送前发生重连、不同 dayStart 的统计一致性、有界队列与生产者保留位置、失败恢复、关闭等待与未订阅 socket 清理、Rust 序列化与实际正文 ETag 一致。
