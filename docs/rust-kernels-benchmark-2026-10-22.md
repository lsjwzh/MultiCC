# 任务搜索与全局 Token 统计 Rust 实现及实测

日期：2026-10-22（北京时间）。代码基线：`e31e00dd`。本报告记录实现与本机验证，不代表已发布或已替换运行中的服务。

> 2026-11-06 注：Node 实现已删除，Rust 是唯一实现。下文的 `MULTICC_RUST_BACKEND`、`MULTICC_RUST_SEARCH`、`MULTICC_RUST_USAGE` 不再被读取；原生模块缺失或版本过旧时相关接口直接报错，不再回退 Node。`npm run benchmark:rust` 与 `scripts/benchmark-rust-kernels.js` 已随 Node 对照一起移除。以下内容保留为当时的实测记录。

## 结论

两个模块已通过 napi-rs 接入 Node，随 Electron / standalone 打包的构建路径已接入。性能收益有限且取决于边界开销：3,000 个任务复用索引查询约快 1.48 倍，含每次内容指纹校验的缓存调用仅约 1.06 倍；约 101 MiB 的 Token 扫描约快 1.33 倍。更明确的收益是把重建索引和扫描计算移到工作线程，降低主线程停顿。

不应把这次结果外推成“整个后端快数倍”。Node 版本也获得索引复用和只给最终结果生成高亮的优化，这些收益独立于 Rust。

## 实测方法

- 机器：Apple M4，macOS / arm64，Darwin 24.3.0。Node v26.8.1，Rust 1.98.0，release 构建。
- 每组预热两次，交错执行 Node / Rust，计时九轮，报告中位数；P95 采用九个样本的最近秩，实际等于本轮最大值，仅用于观察波动。
- 使用确定性合成数据。每个任务有标题、描述、模块标签与八条摘录；查询为“全文检索 索引”，返回前十条。
- Node 对照包含同样的索引复用、内容失效判断和最终结果高亮优化。Rust 总耗时包含 Node 数据准备、跨语言序列化、异步调度、Rust 计算、结果排序与高亮。
- 缓存调用测量路由背后的搜索函数，不含 HTTP 网络、鉴权与响应发送。
- Token 使用八个临时文件，Claude / Codex 各四个；含重复记录、损坏尾行、较大正文、累计用量与无关工具事件。测量目录枚举、文件读取、解析、聚合和结果返回。
- 文件扫描已经预热 OS 缓存，不是物理磁盘冷读。绕过已有两分钟应用缓存；缓存命中本身不计入 Rust 加速。
- 每组先逐字段比较结果，强制 Rust 模式禁止静默回退。基准完成时原生搜索执行 105 次、统计 24 次，回退为零。
- 未扫描私人历史来生成此报告，未测生产并发吞吐和内存峰值。

## 任务搜索耗时

| 任务数 | 路径 | 优化后 Node（ms） | Rust 总耗时（ms） | 加速比 |
|---:|---|---:|---:|---:|
| 100 | 重建索引并查询 | 5.467 | 3.933 | 1.39× |
| 100 | 复用索引查询 | 0.174 | 0.123 | 1.42× |
| 100 | 复用索引并做内容校验 | 0.446 | 0.428 | 1.04× |
| 1000 | 重建索引并查询 | 48.126 | 37.099 | 1.30× |
| 1000 | 复用索引查询 | 0.818 | 0.492 | 1.66× |
| 1000 | 复用索引并做内容校验 | 2.909 | 2.611 | 1.11× |
| 3000 | 重建索引并查询 | 137.600 | 114.057 | 1.21× |
| 3000 | 复用索引查询 | 3.316 | 2.238 | 1.48× |
| 3000 | 复用索引并做内容校验 | 10.674 | 10.110 | 1.06× |

3,000 个任务中，Rust 内部索引构建中位数为 90.721 ms，内部查询为 2.176 ms（重建后立即查询样本）。它们与复用索引时的总耗时属于不同测量路径，不能互相相减。完整重建并查询为 114.057 ms。

重复搜索仍会构造完整文档内容指纹，避免任务原位修改、revision 未变或墓碑变化时读到旧结果。这部分在 Node 主线程执行，已成为缓存路径的主要开销。小于数毫秒的差异在不同轮次会波动，不应宣传成稳定倍数收益。

## 全局 Token 用量扫描

| 合成数据量 | Node 中位数（ms） | Rust 中位数（ms） | 加速比 | Node / Rust P95（ms） |
|---:|---:|---:|---:|---:|
| 6.7 MiB | 6.675 | 4.985 | 1.34× | 8.200 / 6.347 |
| 100.8 MiB | 98.179 | 73.675 | 1.33× | 118.458 / 96.979 |

Rust 顺序流式读取 JSONL，只反序列化有关字段，跳过无关正文。保留 Claude 响应去重、Codex 派生线程首快照与继承前缀过滤、跨文件高水位、按模型/日期/窗口聚合口径。扫描结果的 generatedAt 不参与等价比较。

## 主线程响应性

用 1 ms 心跳记录每次运行中的最大回调间隔，再取九轮中位数。它包括系统定时器精度，不等价于用户界面的实际帧率。

| 工作负载 | Node 最大心跳间隔中位数 | Rust 最大心跳间隔中位数 |
|---|---:|---:|
| 3,000 任务重建并查询 | 137.619 ms | 19.732 ms |
| 100.8 MiB Token 扫描 | 11.945 ms | 1.643 ms |

Rust 没有消除全部主线程工作：搜索仍要准备字符串、计算缓存指纹、排序和生成高亮。

## 接入范围与兼容策略

- `native/core`：独立 Rust 业务库；`native/addon`：Node-API 绑定。后续全 Rust 后端可复用核心库。
- `/api/task-board/search` 使用可切换后端。任务自动归类的同步调用链继续使用 Node 搜索，消息全文检索的 SQLite FTS 路径也保持原状。
- 全局 Token 的 `getGlobalUsage` 接入原生扫描，仍保留两分钟缓存和并发请求合并；Node 负责文件枚举与窗口边界。
- NFKC、小写转换、UTF-16 高亮、本地化同分排序由 Node 保持原契约；Rust 持有索引并计算分词与 BM25。
- 时区由 Node 显式传入 Rust 的 IANA 时区库，覆盖 UTC、上海、纽约及夏令时转换；不是假定所有机器都在同一时区。
- 原生任务在 libuv 工作线程执行，最多同时执行两个、排队十六个。
- 模块缺失时 `auto` 使用 Node；原生失败时告警一次并回退。孤立 Unicode surrogate、闰秒、极端年份及无法兼容的日期/字段表示会回退，避免悄悄漏算。强制 `rust` 模式直接报错，搜索路由返回 503。
- 只保留一个搜索快照；内容变化重建，同一快照并发构建合并。

## 构建、验证与切换

构建需要开发者安装 Rust/Cargo。构建产物默认在系统临时目录；正式使用应指定主仓库的数据目录或其他持久目录，不能存于可回收的任务工作区。最终安装包携带 `.node` 文件，用户无需安装 Rust。

```sh
npm run build:rust -- --out /持久目录/rust-kernels
export MULTICC_RUST_ADDON=/持久目录/rust-kernels/darwin-arm64/multicc_core.node
MULTICC_REQUIRE_RUST_TESTS=1 MULTICC_RUST_BACKEND=rust npm run test:rust
npm run benchmark:rust
```

上例的平台架构目录须替换为当前目标：`darwin-arm64`、`darwin-x64`、`linux-x64`、`linux-arm64` 或 `win32-x64`。交叉编译还需要目标标准库和对应链接器。

| 设置 | 作用 |
|---|---|
| `MULTICC_RUST_BACKEND=auto` | 默认；有兼容模块时使用 Rust，否则回退 |
| `MULTICC_RUST_BACKEND=node` | 全部使用优化后的 Node |
| `MULTICC_RUST_BACKEND=rust` | 强制 Rust，失败明确报错 |
| `MULTICC_RUST_SEARCH=node` / `rust` | 单独选择任务搜索实现 |
| `MULTICC_RUST_USAGE=node` / `rust` | 单独选择 Token 实现 |
| `MULTICC_RUST_ADDON` | 指定原生模块绝对路径 |
| `MULTICC_RUST_PREBUILT_DIR` | 打包时按平台目录查找二进制 |
| `MULTICC_REQUIRE_RUST_BUNDLE=1` | 打包缺少目标模块必须失败 |

## 启用建议

这两个 Rust 内核可作为渐进迁移的第一批组件。Token 扫描已有稳定的吞吐与主线程响应性收益；搜索的主要收益在重建时把计算移出主线程，重复查询的端到端速度还受内容校验限制。若后续继续优化，应先建立可靠的任务索引更新/失效接口，减少每次查询全量生成指纹，并使用真实规模与并发负载复测。
