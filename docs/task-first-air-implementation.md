## 2026-09-11：Air 接管管理首页与子页面外壳

`/manage?view=tasks` 等旧书签分别映射到 Air 的定时中心和任务规划。显式 `/manage.html` 暂时作为
兼容与恢复入口保留，不再是默认导航目标。

- “服务与文档”已经改成 Air 原生列表和登记弹窗，保留打开、启动/停止、日志、置顶和删除能力；
  未配置启动命令的服务会明确禁用启动按钮。
- “设置”成为 Air 原生分类首页。CLI / Provider 已进一步替换成原生 Air 子页，按协议展示线路，支持
  全局 Claude / Codex 默认值、cc-switch 同步、新增、编辑、删除、测速、模型目录和 Claude 分级映射；
  官方多账号、借道分享及 ZCode / Kimi 原生登录暂收在同页的高级兼容区。Goal、语音、全局设置、
  推送、隧道、桥接、资源、Skill 同步和存储均从同一 Air 壳进入；尚未逐项重写的复杂表单以显式
  兼容层嵌入，隐藏旧导航和旧顶栏，继续使用原 API 与校验逻辑，避免视觉改造破坏配置能力。
- 任务规划和记忆也已归入 Air 路由及统一侧栏；后续按子页面逐个把兼容层替换为原生 Air 组件，
  不再新增第二套管理首页。

自动化覆盖 `/manage` 重定向、桌面控制台、原生服务登记、设置分类和 390/320px 管理首页；真实
Chromium 额外验证了 Provider 兼容页已隐藏旧导航并保持表单可用。

## 2026-09-11：Air 对话复用完整 Chat 与目录任务首页

Air 任务页不再使用精简 task-shell 重做聊天区，而是把原 `chat.html` 作为固定任务的完整渲染器。
改造边界是视觉排布和入口收纳：消息历史、Markdown、tool use、运行事件、FIFO、classify、Goal、
待答、附件、语音、上下文、用量、合并与 diff、产物等原有控制器继续工作。桌面低频控制统一进入
“更多”菜单，窄屏重新排布输入区；普通 `/chat` 书签仍解析到 Air，只有 Air 内部带 `air=1` 的任务
iframe 可以直接取得完整 Chat，避免重新出现第二个面向用户的聊天入口。

归档或只读旧任务没有可写 session 时，仍进入完整 Chat 的只读快照模式：按 taskId 分页读取历史，
继续使用同一消息、Markdown 和工具卡渲染器，并投影已持久化的 FIFO/classify 状态；不会退回 task-shell，
也不会在 iframe 中再次嵌套 Air。

- 任务进度卡以连线节点展示“本轮成功、代码交付、源现场稳定、归属生效”，四项仍是相互独立的
  真实事实；候选归属不会因为视觉上连成流程就被当作已经生效。
- 目录列表已进入 Air 控制台首页。进入某个工作目录时，首页先展示该目录任务总览、状态统计和最近
  任务；底部输入胶囊可以附带文件、选择 CLI、标记 Goal，并以原 task-first receipt 通道创建固定任务
  后发送首条消息。创建记录和开始执行仍是两个步骤，失败重试不会重复造任务。
- Chromium 回归直接检查完整 Chat DOM 与工具卡渲染、FIFO/classify 状态、低频控制收纳、任务产物、
  目录快捷创建、控制台目录入口，以及 1366、390、320px 无横向溢出；task-first 99 项及行预算通过。

## 2026-09-11：定时规则绑定固定 Air 任务

中央定时任务不再把每次触发投递到临时角色 Chat，也不会因任务化会话拒绝裸投递而轮换新 Chat。
每条规则现在持久保存唯一 `taskId`，由 task-shell 的 receipt / outbox 通道向该任务发送指令；
任务空闲时直接接收，忙碌时排队，后续触发始终续写同一任务历史。删除时间规则只停止调度，
不会删除固定任务和既有历史。这里的中央 cron 与单会话 trigger 仍是两套明确分离的能力。

- 创建规则时先创建并持久化固定任务，成功后规则才对调度器可见；失败时不留下半条规则。
  规则绑定后工作目录和初始 CLI 不再从 cron 侧修改，CLI、Provider、模型、推理强度和角色统一在
  固定任务的 Air AI 配置中维护。
- 存量规则启动时幂等迁移：优先复用 `lastSessionId` 已绑定的可写任务；找不到可复用历史时才创建
  新任务。迁移等待 task-shell 仓库恢复完成，并以 `taskBindingVersion` 标记结果，避免启动竞争生成
  空任务。历史任务已经归档时不擅自复活，而是为规则建立新的固定任务。
- `/air?view=schedules` 成为定时任务的主界面，展示规则时间、启停状态、最近触发、固定任务、
  运行次数和队列结果；可以新建、编辑、暂停、立即投递或删除规则。固定任务卡直接进入同一个
  Air 对话。旧 `/manage?view=cron` 只保留兼容入口和迁移说明。
- 生产 6 条存量规则均已写入版本化绑定，其中 5 条启用；3 条成功回接最近历史任务，2 条复用
  原固定任务，1 条因旧任务已归档而保留新固定任务。启动竞争期间产生、且确认无消息并未被任何
  规则引用的 3 个临时任务已安全删除。验收未手动触发任何真实业务规则。

验证覆盖固定任务迁移、同任务连续投递与忙碌排队、创建失败闭合、任务历史保护、完整 task-first
回归，以及真实 Chromium 中的 6 条生产规则、创建/编辑弹窗和固定任务跳转。

## 2026-09-11：Air UI 结构收口与生产验收

本批按 R2 计划和“设计 MultiCC 新版视觉”的历史决策收口 `/air`，不改变下方安全边界。
目录与任务合并到唯一的磨砂侧栏；工作目录仍是一级导航，并提供目录库、最多五个收藏、
`⌘ K` 和跨目录活动。任务页只保留一个主头部与一个任务对话，固定角色会话不再回流。

- 任务头部分开显示本轮执行、任务生命周期和工作目录资源状态。成功、失败、等待回答、
  资源容量、归属候选、交付记录过期等状态进入统一进度卡；下一条消息的真实目标始终明示。
  “本轮成功”“代码已交付”“任务完成”“归属生效”继续是不同事实，界面不互相代替。
- 详情改为默认收起的右侧抽屉，分成计划与生命周期、代码与交付、角色与上下文、执行资源
  四组。自动重归属仍关闭；界面只显示候选及阻塞条件，不把候选写成已应用归属。
- 对话区区分用户消息、本轮结果和低权重证据；产物入口并入底部输入胶囊。
  轮询不再重绘未变化的历史，任务草稿按 taskId 保存，切换目录或视图不会误投消息。
- P00–P15 等批量实施包曾是 2026-09-10 明确登记的 `planned` 任务，不是 Air 临时生成；
  这批空计划任务已于 2026-09-11 按用户要求安全删除。以后真实创建的计划任务即使还没有聊天消息，
  仍会展示任务说明、验收标准和工作阶段，并明确标记“尚未执行”；首次打开只建立恢复元数据，
  不伪造一条用户消息，发送第一条消息后才开始执行。
- 任务 AI 配置沿用旧设置页的 CLI → Provider → 模型/推理层级，改为 Air 卡片样式。
  Provider 按 CLI 兼容性过滤，支持原生登录、自管/Official Provider 与 Auto 候选池；模型随线路联动。
  保存时先切 CLI、再持久化 Provider 路由，最后单独写模型与强度，避免 Provider 默认模型覆盖用户选择。
- 390px / 320px 下侧栏改为抽屉，详情占满可用宽度，AI、角色和发送入口保持可达，
  页面不产生横向滚动。API 意外返回 HTML 时给出可操作的服务重启提示。

生产验收使用真实数据（20 个目录、1061 个任务）：旧的孤立 `node server.js` 被优雅停止，
当前代码由 PM2 接管 3000 端口；`/api/air` 与任务详情均返回 JSON 200。真实浏览器完成目录库、
跨目录活动、任务路由、失败状态卡、详情抽屉及对话输入检查。自动化验证包括 task-first 93 项、
任务 shell / 产物 / 连续性 50 项、桌面与 390/320px Chromium 回归及行预算检查。
本机 `claude auth status` 当前为未登录；因此选用 Claude 的真实新执行仍需用户完成 Claude 登录。
这是 provider 凭据状态，不由 Air UI 伪装为成功，也未在本批修改任何凭据。

原生 App 聊天组件及未重做的设置页仍保留，不宣称本批发布了新 APK 或完成全部 App 视觉重构。

- 旧 `/chat(.html)?session=…`、独立 task-shell 链接解析到对应任务；Air 内嵌 renderer 只展示该任务。
  显式 task 链接优先于会话游标。终端作为目录下的工具保留。任务产物边栏继续按 taskId 聚合。
- 启动及 Air 读取时幂等迁移存量 Chat，包括指挥官。复用原执行 ID，保留历史、原生句柄、待答和工作目录；
  只有任务登记成功才持久保存反向绑定。角色冻结为任务附件。异常保留记录并在 Air 提示数量，不删除现场。
  任务化不等于删除底层执行记录；这些记录仍负责恢复、回调和 Git 归属。

  存量共享、dirty 工作区保留原路径与引用，并继续由准入/租约阻止冲突，不做自动拆分或交换。
- 计划任务第一次打开时沿用原 taskId 绑定执行元数据，选用可用 CLI；索引失败可重试且不重复创建。
  已经有其他执行归属的历史记录不在读取时抢占现场；不确定的旧任务仍按只读/显式 fork 处理。
- Web 任务头部提供角色和 AI 配置；角色可从模板库附加、编辑或移除。版本化消息角色规则沿用上一批。
  模型/CLI 更改使用既有忙碌保护。角色变化在下次执行时归档旧原生上下文并通过任务历史续接。

## 2026-09-11：交付证据与版本化角色接入

本批继续接通 P05/P06/P07/P10。普通 Chat / 任务现在保存真实最终执行尝试的结果、
本轮代码版本，以及正常合并的发布记录。Air 详情显示本轮结果、交付凭证和待核验条件。

- 代码版本以 tracked / 非 ignored 的 untracked 文件实际字节、路径、可执行位与符号链接形成摘要。

  本轮结束前/后发生的合并、dirty 代码稍后正常提交合并、已在基线的无变化核验均可关联。

  携带受限任务历史；聊天原文、工作目录、项目/私有记忆保留。未确认常驻进程关闭则拒绝切换。
  旧 Web 的角色字段仍是兼容入口；现有任务进入附件模式后由任务角色接口管理，尚未完整迁移所有旧配置入口。

  不再因为 visibility 暂停而缺失数据，显式刷新同时刷新内嵌对话。

## 前一批记录：执行链路与 Air 入口（交付证据进度以上文为准）

本批已把常规 Chat / 任务执行接入持久 Workspace 身份、租约和出队准入，
并新增真实 Web `/air` 首页和 Flutter App 目录任务页。这里不是静态视觉原型。
旧 `/manage`、Chat、Terminal 入口继续可达，App 可切换回会话与终端视图。

- `src/workspace/registry.js`：SQLite immediate 事务统一预留执行、驻留、恢复名额。
  Workspace 使用规范化路径形成稳定 ID，共用目录的会话引用同一 Workspace。
  租约没有“到期就抢占”；重启后无法证明已停止的旧租约标记 uncertain。
- `src/workspace/admission.js`：任务先持久入队，在实际 outbox 出队前创建/恢复并
  验证工作目录，再向运行引擎签发仅进程内可用的 permit。CLI 启动前验证 permit，
  重试沿用本轮租约；终止回调后等待运行状态清理及常驻进程退出才释放。
  活跃后台写入者保留租约。容量不足延期投递，不消耗重试次数。
- `src/session/create-record.js`：独立任务和 fork 只创建会话元数据，状态 planned。
  首次执行再物化；fork 仍按记录的源 commit 建立分支。原会话/终端仍兼容原路径。
  TaskRun 可复用执行槽和实验 TUI 保留其原有准入，不宣称已迁入此新租约。
- Air 创建与发送复用 task-shell 权威记录和 receipt，不创建第二套任务库。
  Web 包含目录库搜索、最多五个本浏览器收藏、任务列表、跨目录执行、草稿保护、
  AI 配置摘要、默认收起的详情及可选角色说明。服务与文档仍为全局入口。
  App 新增原生目录任务页、创建、搜索和全部记录筛选，打开现有原生 Chat 继续工作；
  本批没有把所有 App 设置页/Chat 组件重新设计，也没有发布新 APK。
- 在线目标变化先保存不可变来源的候选，分类器在凭证齐备前不改写任务、消息或游标。
  新输入会让旧候选失效。候选不是正式目标任务 B。

**尚未启用自动归属应用。** 真实最终 attempt、集成 receipt、可持续验证的现场
停写屏障，以及基分支有效性检查尚未组成完整应用事务。界面明确显示保留归属/候选
待核验；不得把 Aux 分类成功或普通父 PID 消失伪造为这些凭证。跨壳接管、撤销与
完整 RoleBinding/ChangeSet 迁移也仍是后续包。

默认名额：执行 8、驻留 128、同时恢复 2，可由 `MULTICC_WORKSPACE_RUN_LIMIT` /
`MULTICC_WORKSPACE_RESIDENT_LIMIT` / `MULTICC_WORKSPACE_RESTORE_LIMIT` 设置。
已驻留的存量目录照常保留；超过驻留预算后新目录会排队。此阶段暂停旧自动休眠，
不自动提交 dirty 或卸载目录来腾出容量。旧进程状态不明的占用需要单独核验，不能
通过浏览器按钮无条件清除。Terminal/外部进程不构成已验证的停写屏障。

验证包括 SQLite 双连接争抢、真实临时 Git 物化、结束回调竞态、模糊启动保留，
Docker 内模拟 Codex 的主流程/容量/取消/重启和 Chromium 操作；不等同真实模型、
真实手机安装或真实未纳管子进程隔离验收。生产服务需要用户手动重启生效。

## 基础批次审查结论（历史）

方向可实施，但必须分阶段接入。最后审查修正了两点：

1. **P01 的基础存储与权威切换分开。** 先增加独立命名空间的持久事实能力，
   不改旧 task-board / task-shell 的写入权威。只有 P03 的旧入口适配和迁移验收完成，
   才进行 P01b 单写权威切换，避免隐含循环依赖或双写。
2. **交付版本不等于合并后当前 HEAD。** 正常合并和 sync-back 会推进源 HEAD。
   凭证需要覆盖本轮 endCodeRevision，并以新的源现场/操作屏障核验稳定性；
   不能要求源 HEAD 永远等于合并前 HEAD，也不能只凭一次 merge 成功放行。

最初基础批次尚未接入在线发送/合并/分类路径；没有切库、迁移角色会话或自动清理目录。
后续不得将“基础测试通过”表述为“R2 自动归属已上线”。

## 必须保持的行为

任务会话产物边栏已接入普通 Chat 与 Air 内嵌任务页。通过当前任务的完整
历史回复/工具成功输出与文档登记表归集 artifact 链接；相同文件去重，登记
记录保留任务 ID、标题和原 URL 参数。旧登记只有专用任务执行会话 ID 可
作为归属依据，不按共享会话批量导入，也不将 fork 的继承上下文算作新产物。
列表只读，支持展开/收起、搜索、复制、新页打开与失效标记，不改变产物
生命周期。按任务保存展开偏好；切换任务使旧请求失效，刷新失败可重试。

- 创建任务/角色附件不应创建 worktree；实际仓库能力执行前按需物化。
- A 中执行 A+，事后分类为 B：先保存候选，正式归属和输入目标仍为 A。
- 本轮最终有效 attempt 必须 succeeded；completed 仅是调度槽释放。
- 代码执行必须有对应版本的有效集成凭证，并验证源现场没有待处理修改、
  未整合提交或未交接文件。源现场在核验到应用之间受持续写入屏障保护。
- 无代码豁免仅允许被宿主核实的隔离讨论，且没有仓库访问、工作区依赖或待交接产物。
- 游标、已接受输入或原 run 发生变化，旧候选不能迟到应用。
- B 忙、dirty 或缺少基线是独立的目标准备状态，不抢占或覆盖 B 的执行。
- B 使用自己的工作区续接已交付基线；WA 不随归属转交或删除。
- 自动重归属不自动启用提交/合并；dirty 默认保留，未知写入者必须阻止回收。
- 原始 run、消息、角色快照、代码与待答/回调来源不因归属修订而改写。

## 第一批代码的边界

### `src/task-routing/eligibility.js`

`evaluateAttribution(facts)` 是无 I/O、无副作用的条件判定。
输出 `state / eligible / blockers / requiresAtomicRecheck`。
`ready` 不是执行许可，不能拿缓存结果直接创建任务、切游标或操作 Git。

输入包含 proposal、run、context，以及代码执行的 source、guard、integration、baseline，
或者 noCode 豁免证明。所有肯定事实必须是明确类型；未知状态阻止生效。

integration 的 `coveredCodeRevision` 对应 run 的 `endCodeRevision`；
guard 的 workspaceVersion 对应当前 source.version。
baseline 需要关联同一凭证、仓库和基分支，并证明集成仍可用。
单凭提交祖先关系不能证明一次 revert 后代码仍有效。

这些是**可信宿主观测的契约**，不是让客户端提供 verified=true。
P06/P07 接入时必须从真实日志/Git/权限/执行结果生成证据；最终应用事务要在
有效屏障内重新检查版本。模块不自行证明任意外部进程已经停止写入。

### `src/task-routing/facts.js`

`createTaskFactsRepository(store)` 复用现有同步 SQLite transaction 接口。
记录均放在 `task-first:` 命名空间，未新增在线数据库文件或修改旧 task/shell。

- appendFact：仅保存不可变 run-result / integration；重复事实幂等，冲突拒绝。
- createProposal：保存不可变定义和初始 pending；相同定义重试返回当前记录。
- recordEvaluation：通过 expectedVersion 更新候选，和领域事件在同一事务提交。
- pendingEvents / acknowledge：重放与确认领域通知，**不是第二个执行队列**。
- stale/rejected 候选不被静默复活；接口不支持直接写 applied。

这只完成 P01a 的事实账本基础，不包含完整 TaskRepository、计划索引或 P01b 权威迁移。
pendingEvents 目前读取命名空间列表，在线接入前需按投递状态建立索引与分页。
任何未来异步/跨库替代 store 必须重新验证事务契约，不能仅提供同名方法。

### `src/workspace/inventory.js` 与盘点 CLI

`inventoryWorkspaces({sessions,directories,observations})` 只处理提供的元数据。
支持旧共享 owner 引用、规范路径观测、同分支多路径、冲突/缺失/循环引用标记。
无路径且引用异常的记录是 unresolved，不能当作新任务尚未分配目录。

```sh
node scripts/task-workspace-inventory.js --input snapshot.json
```

snapshot 包含 sessions[]、directories[]，可附按声明路径索引的独立只读 observations。
输入文件须明确指定；CLI 不探测生产数据根、不写文件、不执行 Git、不建目录。
返回 `read-only-preview`，所有工作区 `canAdopt=false / canReclaim=false`。
没有文件系统观测则标记 unknown；任务 succeeded/done 不构成 clean 证据。

覆盖范围仅是所提供的 session 声明，不是磁盘上的全部 worktree：
隐藏任务、孤儿检出、历史分支与 retiredWorktrees 需后续独立盘点。
检测到 retiredWorktrees 会明确标记未核验，不能据此自动导入或回收。
