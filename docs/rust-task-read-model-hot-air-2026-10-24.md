# Rust 任务读模型：热路径与 Air 契约隔离验证（2026-10-24）

本轮用户已授权默认接入 Rust 并提交合并，最新接入范围见 [Air 摘要读模型默认使用 Rust](rust-air-read-model-2026-10-24.md)。下文保留为接入前的阶段记录。


本轮完成两项：让热缓存、元数据与单卡实时覆盖复用 Rust 已有摘要；实现并对照验证消费宿主卡片的 Rust Air 索引及增量重放。产品路由、运行中的配置与默认实现没有切换。本轮没有提交、合并、推送或重启服务。

结论：Rust 的冷读及数据库变更后刷新仍有收益，热缓存请求仍慢于 Node。不能据此直接替换生产 Air。完整 SQLite 摘要读取与 Air 卡片消费是两个隔离的入口，本轮没有把它们自动拼成生产链路。

## 实现与输入契约

Rust 保留独立的源摘要、叠加后的卡片、输入覆盖、位置索引与有界查询缓存。正常刷新只读 SQLite；元数据变化不再重读任务正文。单卡覆盖变化先完成所有字段校验，再只替换对应卡片并清除查询缓存。白名单覆盖不能修改 ID、消息时间或更新时间，因此此时无需重新排序。覆盖清除从原始摘要恢复字段，不会遗留旧状态。

旧的 refresh 仍表示全量替换 metadata 与 overlays。新增 sync 明确表示复用与增量，避免依赖会被原地修改的 JS 对象引用：

- 省略 metadata：复用 Rust 上次接受的元数据；提供 metadata：完整替换；显式 null：拒绝。
- overlayChanges 按任务 ID **完整替换该任务的覆盖对象**；null 删除该任务覆盖；省略的任务保持原值。字段不是深度合并。
- 可传 baseRevision；版本过期直接拒绝，失败不改变上次快照或输入状态。
- 即使省略全部输入，仍检查源文件身份、schema 和持久连接的 data_version。数据库变化会重新读取，损坏行会报错，不能静默把旧快照当成新鲜数据。
- view 在一次异步原生调用内返回分页与统计；查询前仍须成功 refresh 或 sync。它本身不刷新数据库。

数据库提交后仍是整批读取，尚未实现逐行数据库变更日志。源摘要增加了一份常驻内存，不能承诺总内存下降。

## Air 契约范围

同一原生模块新增独立的 air 命令空间，open 接收宿主生成的随机 epoch；apply 接收宿主已经生成的安全、可见卡片，并支持 partial/removed；changes、page、stats、bootstrap、snapshot、cursor 由 Rust 执行。重新 open 创建新代际，不复用旧历史。

验证包含：首轮 reset、无变化不推进游标、全量缺失删除、逐卡删除、仅元数据更新、历史窗口过期、异代/未来/非法游标、超过 64 帧重置、单帧及累计字节上限、最终状态合并、删除后重建、引导集合与提醒上限、置顶/包含项、筛选、统计。历史上限默认 256 帧，单次与累计补齐默认 256KiB；配置上限为 4096 帧和 16MiB。

字节计数在 Rust 使用 ryu-js 1.0.3 对齐 ECMAScript 的有限数字编码，避免 0.000001、科学记数、小数及负零在 JSON 边界附近产生不同 reset 判定。测试覆盖中文和 emoji 的 UTF-8 字节边界。

隔离测试直接使用现有 mountAirRoutes 的卡片生产者：合并、删除、内嵌、未就绪拆分任务不进入集合；拆分就绪后进入；宿主生成的 readOnly、线路、goalState、runState、Git 变化和容量原因逐字段保留。隐藏 ID 即使出现在 bootstrap include 中也不会复活。另将 Rust 引导和重放响应直接交给现有 public/air-sync 客户端，验证重复帧、离线补齐与换代恢复。固定种子的 180 次混合变更持续与现有 Node 索引对照。

**这证明的是消费契约。可见性/权限、Git、容量、派发宽限等判定本身仍由现有宿主负责，没有迁入 Rust。** 输入必须来自安全卡片生产者，不能把完整会话或原始任务正文直接当作 Air 卡片提交。重复 ID、无效状态类型和无效数字明确拒绝；JSON 字段顺序变化本身不视为语义变化，不承诺与 Node 的 JSON.stringify 字节序完全一致。

尚未迁移兼容全量 HTTP 的 serialized/ETag，也未把原生异步查询接入现有同步 HTTP/WS 宿主。尤其 attach 中“读取补齐窗口并订阅实时事件”的原子性需要专门设计异步边界；本轮客户端对照不代表已验证真实 WS 交接竞态。

## Node 例外

产品 Node 新代码仅保留原生异步调用、JSON 边界、有界 FIFO 队列及历史 ID 的 ICU 排序桥接。历史 ID 排序不能直接改成 Rust 字节序；Rust 先确定候选 ID 集合，Node 用现有 localeCompare 排序后最多重试一次。排序/输入有效性及状态发布由 Rust 校验。后续固定 locale 与 Unicode 契约后再移除 ICU 适配；独立 Rust 服务接管原生传输后再移除 N-API 桥接。

测试与基准中的 Node 复用实现只作为对照，位于 tests/helpers，不被产品入口引用。

## 性能方法

Apple M4 / darwin arm64 / Node v26.8.1。开始时间 2026-10-23T17:31:51.473Z。沿用上一轮脚本，新增 Node 复用基线及单卡覆盖场景：

1. node-current：生产任务壳行缓存和 Air 索引，配当前 Rust SQLite 驱动。
2. node-native：相同 Node 业务及缓存，配旧 Node SQLite 驱动。
3. node-reuse：相同驱动、同一生产 Air 索引，另在测试辅助中明确保留输入与源行索引；无变化直接复用，仅元数据或单卡变化走 partial apply。给予 Node 与 Rust 同等的输入复用优化机会。
4. rust：首轮完整输入，后续 sync 复用或增量输入，分页与统计合并为 view。

当前驱动及 Rust 读取模型使用 SQLite 3.50.2；旧驱动使用 SQLite 3.53.4。4 组数据 × 4 个后端 × 6 个场景 × 11 轮，共 1056 个计时样本，每个场景另预热 2 轮。计时包括边界编码、排队、原生计算、解码与查询；不是磁盘冷缓存或生产 HTTP 延迟。基准期间未并行运行本轮编译或回归测试。

三个合成规模为 100、3000、10000 条，每条有 8192 字符上下文。本次源数据库只读事务捕获 1131 条任务行、11,210,494 字节，在临时仅任务表副本中分别计时；不是完整生产数据库物理布局。所有计时写入都发生在临时副本，结束清理。每轮核对刚变更的任务，场景结束逐字段核对完整摘要、分页和统计。

以下为中位数，原始 JSON 另含样本、P95、CPU、心跳探针和进程峰值 RSS。11 个样本不足以外推生产 P95。运行顺序固定，机器其他负载仍可能影响结果。
