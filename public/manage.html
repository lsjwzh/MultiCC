Claude Code 代理路由
让 Claude Code 的主进程与 Task 工具派生的 子任务 (subagent) 走不同 provider/model——原生 Claude Code 做不到（subagent 是进程内 sidechain，共享主进程的单一客户端）。开启后，每个会话可在 chat 的 AI 配置里单独指定「子任务 provider+model」（chat 输入框上方有「子任务」指示条，点击即改）。
· 开启：所有配了 provider 的会话，请求经本地代理 (127.0.0.1) 中转再打到真实 provider；真实 token 不进子进程（更安全）；子任务可独立路由。代价是多一跳 localhost 转发（开销可忽略），代理是所有 provider 请求的单点（出问题会影响全部 provider 会话，可随时在此关闭）。
· 关闭：claude 直连各自 provider，子任务与主进程同 provider/model；更简单稳妥，但失去子任务独立路由能力。默认登录会话（未配 provider）无论开关都直连，不受影响。
官方会话走代理 (OAuth 重放)
让「主 provider = Claude 官方（OAuth 订阅登录）」的会话也经本地代理中转——代理从 macOS 钥匙串读取订阅 OAuth token 转发到 api.anthropic.com。唯一作用：让官方会话的 Task 子任务也能路由到便宜 provider（否则官方会话直连、子任务只能与主进程同用官方）。需先开启上方「代理路由」。
· 关闭（默认，推荐）：官方会话直连 Anthropic，子任务无法独立路由。零风险。
· 开启：⚠️ 会在官方客户端之外重放订阅 OAuth token，可能违反 Anthropic 服务条款、有账号风险；且与 CLI 共用同一钥匙串条目。仅只读钥匙串（不刷新），token 过期后需运行一次 claude。知情自担风险再开。
关盖运行 · macOS
开启后会阻止所有系统睡眠（包括关盖睡眠）。切换时需要在 Mac 上完成管理员授权，请注意散热和耗电。
