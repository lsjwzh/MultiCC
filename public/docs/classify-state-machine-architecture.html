1. 当前输入 → 判定 → 输出大图

绿色部分是已经正确拆出的纯规则；红色节点同时做 guard、调度和多路投影，是当前复杂度与一致性风险的中心。

关键错位：正常 durable assistant result 只证明 turn succeeded；当前链路却把它渲染为“任务完成”，并把 TaskBoard 设为 done。

2. 当前字母的实际含义

字母本身不是问题；问题是一个字母同时承担 turn、task、scheduler 和 presentation 四种语义。

Prunner active，或 ownership unknown。调度不放行普通旧 FIFO。
Dcompleted boundary。实际是 turn 成功；当前展示和任务看板却当作 task 完成。
W存在未解决的结构化用户问题。释放 active，等 answer / direct input。
B后台 callback 未回流。释放 active，等 callback / continuation。
E异常、中断、持久化失败、用户/看门狗取消的合集；必须靠 reason 区分。
优先级事实结果说明
1ownership = active/unknownPclose 候选不可提交；unknown 也 fail-closed。
2pendingUserInputW结构化问题证据优先于 clean close。
3backgroundPendingB后台任务仍会回流。
4boundary = completedD只代表本轮结果正常持久化。
5abnormal / unknown boundaryE未知 boundary fail-closed，不误判成功。

3. 正常 Chat turn 的真实时序

`completeSessionTurn()` 以 fire-and-forget 启动；classify writer 发起 scheduler transition 后也不等待。取消路径会补等 pending transition，普通路径不会。

4. 审计发现与优先级

优先处理跨层语义与一致性；目录拆分排在后面，避免只是搬运错误模型。

P0D 的证据层级错误

completed boundary 证明 turn 成功，不证明整个用户任务完成；当前却自动 phase=done、TaskBoard=done、推送“任务完成”。

P1guard 前已有写入

history、goal/phase、TaskBoard 在 liveness guard 之前写入。直接调用者可形成部分提交。

P1scheduler transition 不 await

普通 D/W/B/E 先投影后等待调度；scheduler reject 时没有 rollback。取消路径单独补 await，主路径缺失。

P1Terminal 复用 Chat ownership

Terminal 没有 chat runtime，ownership=unknown；旧模型结果被 hold，日志、TaskBoard 和 persisted state 可分裂。

P1Aux prompt 与重试成本无界

最近 20 条完整内容没有总 budget；归集失败的 session 在 throttle 过期后可能每 60 秒再入队。

P2多写者 + 非法 P 隐藏

多个模块直接写 P；turn-end P 又被静默变 W，违规 transition 没有暴露。

P2live / recovery 形态不同

运行时 W/B/E 释放 active；重启恢复可制造 legacy-active/frozen，相同事实不同内部形态。

P3legacy 与展示漂移

旧三行状态模型、C、旧文档仍在；App phase switch 缺 implementing/wrapping。

5. 静默卡住：当前安全判断

静默是负证据，默认不能获得 kill 权限。只有显式 opt-in 才会把连续 stalled 观察升级为取消。

已修复：默认策略不再依据负证据自动结束 turn；静默误杀保护提交为 024f3cd，已包含在本审计基线。

6. 目标：两个状态域 + 一个提交协调器

调度只关心 turn outcome；TaskBoard 只关心 task lifecycle。二者通过显式事件关联，不能再把 turn.succeeded 当 task.completed。

目标不变量：turn.succeeded ≠ task.completed；liveness 只决定“能否 commit”，不决定业务结果；Aux 只命名，不写运行状态。

8. 最小迁移顺序

先修语义和提交一致性，再做目录重构；每一步都能独立验收和回滚。

D 改为 turn succeeded保持协议字母兼容；展示“本轮完成”，停止 D → TaskBoard done，增加显式 task.complete。
引入 coordinatorguard 前零写入；await scheduler；提交成功后再统一驱动 taskState、UI、TaskBoard 和 push。
迁移 Terminal使用 terminal process/monitor boundary，不复用 Chat ownership，删除 idle-tail 状态模型的写权限。
限制 Aux 成本总 prompt budget、prompt hash、attempt/result 时间、指数退避和失败上限。
统一 recovery无 durable active delivery 不制造 legacy active；修订 FIFO/status/cancel 文档与契约测试。
